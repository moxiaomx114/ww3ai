# 飞行模型参数体系与标定方法

> 本文描述「有哪些参数类型、各自影响什么、我们如何标定」，供调参和排障时定位问题。
> **本文不附任何第三方参数原值、字节码或反编译产物**；具体数值请从你本地安装的
> ww3 content pack 读取，不同版本可能变化，照抄别人的数字既不可靠也没有许可依据。
> 我们的基线全部来自**实测行为反推**：离线仿真里的每条断言都可以复现。

---

## 1. 参数体系（类型 → 物理含义 → 标定方法）

气动模型的参数按作用分为四组：

| 参数类型 | 物理含义 | 标定方法 |
| --- | --- | --- |
| 推力系数 / 推力-速度曲线 | 不同速度下的可用推力 | 在不同速度段做阶跃油门输入，拟合稳态加速度 |
| 基础阻力 / 诱导阻力 / 阻力-速度曲线 | 零升阻力与升致阻力 | 滑翔减速试验：收油门后按速度衰减曲线反推 |
| 升力系数 / 临界迎角 / 最大迎角 | 最大可用升力与失速边界 | 逐渐增大迎角，记录升力转折点与失速 onset |
| 操纵权限 / 各轴角速率 / 响应延迟 | 舵面有效性随速度的变化 | 满舵阶跃，测稳态角速率与 onset 延迟 |

同一套参数在不同机型上差异很大，因此**任何按速度设定的阈值都要按机型分别给**，
用一套全局值喂两种飞机必然有一边不准。

### 接口定位

以下类名只作为「去哪里找接口」的定位提示，本仓库不附它们的实现或字节码：

- `ww3.core.physics.models.AirplaneFlightModel` 及其 `Options` —— 参数结构
- `ww3.core.physics.models.ControlAuthority` —— 杆量整形与回中
- `ww3.core.entities.vehicle.input.VehicleInputHandler` —— 输入通道

机型参数以明文 jsonc 形式放在本地 content pack 的 `core/physics/` 下，
按机型命名，**机型文件名与游戏内载具 id 不一定相同**，用之前先确认映射。

## 2. 值得注意的机制（定性）

这些结论不依赖具体数值，是调参时最容易踩坑的地方：

1. **杆量是整形过的，不是线性**。输入经过非线性映射后才成为舵面指令，
   所以内环先把被控对象反演成「单位增益 + 纯滞后」，再上速率环；否则增益整定没有意义。
2. **操纵权限随速度增长**。低速段权限不足，高速段满权限，
   因此在低速段再叠一层权限裁剪会把飞机锁死；该限制的是**迎角**，不是杆量。
3. **阻力随速度平方增长，推力近似恒定**。结果是存在一个**气动极速**——
   不是代码里的 `maxSpeed` clamp，而是推力与阻力自然平衡的点；放起落架会明显降低它。
4. **FCS 有迎角与过载限幅，且不同机型策略不同**：有的软限、有的硬断。
   别把一架飞机的迎角边界套到另一架上。
5. **起落架阻力是渐变量**，不是收/放开关；过渡期间的阻力变化会污染稳态速度样本。
6. **方向舵权限远小于俯仰与滚转**，协调转弯必须给前馈，
   否则方向舵长期饱和、满舵指令会盖掉真正需要的机动。
7. **运行时暴露的传感器量与我们需要的量不完全对应**。
   角速度、迎角等需要按机型的符号约定逐轴校准；符号接反会让速率环变成正反馈，
   表现为绕纵轴高频翻滚。排障时**逐轴二分**，绝不三轴一起翻。

## 3. 对 AI 控制律的直接影响

| 结论 | 落地做法 |
| --- | --- |
| 参考速度不等于可达速度 | 把「油门 trim 的目标速度」与「能量/保护阈值的参考尺」拆成两个独立配置；前者按机型极速的约 70% 油门稳态点给，后者保持原标定，避免把改出门槛一起缩放掉 |
| 失速是迎角问题，不是速度问题 | 保护逻辑优先用实测迎角判据；高速大迎角同样危险，只看速度会漏判 |
| 增益受滞后限制 | 舵面响应有延迟，速率环增益过大会自持振荡（升降舵每 tick 反向的「抖杆」）。正解是降增益，不是给输出加 clamp |
| 不同机型极速不同 | 同一全局巡航目标必然让某架飞机长期满油门、报警刷屏；这属于配置基线错，不是引擎或控制律故障 |
| 机动进入速度要现实 | 若某动作的最低进入速度高于机型物理极速，它会永远选不出来；日志里的 `NO_MANEUVER` 要先查门槛，不要先调增益 |

当前默认配置里，`flight.trimSpeed` 专供油门环，`flight.cruiseSpeed` 保留为保护阈值参考尺，
`flight.ratePGain` 取偏保守值以压住抖振——这三条都是上述结论的直接结果。

## 4. 怎么复现这条基线

不需要反编译任何第三方产物，三条路就够：

1. **离线仿真**：阶跃输入、滑翔减速、迎角扫描、满舵阶跃，各跑一组，拟合出上面的参数类型。
2. **实机稳态采样**：取「收轮、满油门、平飞、无转弯」的速度样本做上界，
   注意盘旋与诱导阻力会让实测值低于理论平衡速度。
3. **交叉验证**：把拟合结果放回仿真，看稳态速度、改出时间、编队间距是否同时吻合；
   只对上一个量的参数几乎一定是错的。

> 标定结论写进文档时只记「类型、含义、方法、定性机制」，
> 不记第三方参数原值——既避免版本漂移，也避免许可问题。
