## 一、这是什么

`ww3ai` 是一个 Forge 1.20.1 的附属模组，把 ww3 里的载具变成能自主空战的 AI 战机。它做三件事：

1. **接管飞行**：以 20 Hz 的频率直接写杆舵与油门，完成巡航、追瞄、规避、爬升、脱离。
2. **决定战术**：可以只用内置规则脚本（零网络、零配置），也可以给每架飞机单独绑定一个大模型，由模型在关键时刻选择"进攻 / 拉开 / 防御转弯 / 摆姿态 / 撤退"。
3. **管住武备**：自定义挂架配置、保存成蓝图、用部署器在任意坐标成批投放。

### 核心设计：大脑与躯干分离

```
            ┌─────────────────────────────┐
  0.5–2 Hz  │  模型层（可选）              │  只输出三个字段：
            │  attack / extend / patrol …  │  action, desired_alt, fire
            └──────────┬──────────────────┘
                       │ 意图，不是杆量
            ┌──────────▼──────────────────┐
   20 Hz    │  规则控制器（永远在跑）        │  三级级联：姿态 → 角速率 → 舵面
            │  舵面 / 油门 / 扳机           │  ＋ 能量环（油门跟速度误差）
            └─────────────────────────────┘
```

这条边界是整个模组最重要的承诺：**任何模型都不可能直接把飞机拉进地面**。模型给的是"打还是跑"，怎么打由控制器负责。

内环为什么是三级（而不是一个"角度误差 → 杆量"的 PID）：

- **姿态层**把"往哪飞"换成"抬头/滚转速率该是多少"，用的是时间常数而不是拍脑袋的增益；
- **速率层**拿实测角速率做 PI **＋ 前馈**，并按空速调度——舵效随动压走，同一根杆在 70 m/s 和 200 m/s 完全不是一回事；
- **能量层**让油门负责速度误差、俯仰负责航迹，爬升要花油门，而不是偷空速。

倒扣、失速这些以前靠特判兜住的姿态，现在是这套结构自然的结果：角速率不会在 180° 处跳变，拉杆在机体坐标系里也不会再把机头按向地面。

**这套内环不是自创的**，是照着两个飞了十几年的开源飞控移植的：

| 拿过来的东西 | 出处 | 解决的具体毛病 |
|---|---|---|
| `sqrt_controller`（近端线性、远端开方，再加"一步之内不许越过误差"的钳位） | ArduPilot `AP_Math/control.cpp` | 大坡度指令一拍打满舵；过冲在数学上被禁掉 |
| 非对称俯仰角速率上限（抬头 35、低头 60 °/s） | ArduPilot `2SRV_RMAX_UP/DN` | 投放瞬间猛拉杆把攻角顶过 17° 失速 |
| 转弯协调抬头偏置 `\|g·tanφ·cosθ/V·sinφ\|` | ArduPilot `2SRV_RLL` | 压坡度后不补抬头 → 慢慢下沉的螺旋 |
| 速率前馈（FF） | PX4 `FW_PR_FF`、ArduPilot `RATE_FF` | 只靠 PI 时"先滞后、再过头"的发飘手感 |
| 高频增益压缩 `RATE_SMAX`（P+D 一起压，最低 10%） | ArduPilot `AC_PID` + `SlewRateLimiter` | 20 Hz 抖动：不是硬切杆量，而是把环的相位补回来 |
| 空速平方增益调度 `(trim/V)²` | PX4 `airspeed_scaling` | 同一套增益低速没反应、高速抽舵 |

**更关键的是：ww3 的飞机是"速率指令"模型，不是力矩模型。**

读 `ww3/core/physics/models/AirplaneFlightModel.applyAngularControl` 和 `ControlAuthority`，操纵输入是这样用的：

```
authority  = clamp((speed − authorityStartAtSpeed) / (authorityFullAtSpeed − authorityStartAtSpeed), 0, 1)
targetRate = shapeQuadratic(stick) × rateMax × authority        shapeQuadratic(x) = sign(x)·x²
```

三条推论，旧控制器全踩了：

1. 杆量→角速率是**平方**的，线性增益只在一个杆位上正确。要 30 °/s 俯仰时给 0.37 杆，实际只得到 **4 °/s**（13%）；
2. `rateMax` **每架飞机不同**（见下表，滚转从 30 到 220），一套固定增益不可能同时适合喷气机和直升机；
3. 权限在 **40 m/s 就饱和**（Gripen 30、A-10 从 20 起算），**不是**动压 V²。按 V² 调度会在 200 m/s 弱 2.4 倍、70 m/s 强 3 倍。

所以速率环现在做的是**精确反演**：`stick = sign(u)·√(|率指令| / rateMax)`，PI 只修剩下的残差。这些数字是运行时用反射从 ww3 自己的 `Options` 里读的，改内容包也自动生效。

| 机型 | rollRate | pitchRate | yawRate | 权限区间 (m/s) |
|---|---|---|---|---|
| f15e (eagle) | 140 | 30 | 5 | 10–40 |
| su33 | 140 | 40 | 6 | 10–40 |
| jas39c (gripen) | 220 | 35 | 5 | 10–30 |
| av8b (harrier) | 160 | 27 | 4 | 10–40 |
| a10c | 90 | 35 | 7 | 20–40 |
| ah64 | 30 | 45 | 30 | 恒定（无速度曲线） |

数值验证（用上面这个真实模型，指令取各机型全杆的 60%）：六种机型的稳态误差都在 0.5% 以内，积分项结尾 ~0——说明前馈本身就把活干完了，PI 只是在补残差。

没移植的：完整 TECS（需要阻力模型和油门-推力模型，ww3 不提供）、ArduPilot 的二阶输入整形（假设 400 Hz 环，20 Hz 下 `sqrt_controller` 已经够）、陷波滤波与自动调参（游戏里没有传感器噪声）。

#### 角落速度：为什么"打满杆"在低速不是转弯

ww3 的 `fcsLimitPitch` 会把俯仰杆量钳到 `fcsMaxAOA`。所以**打满杆得到的是"攻角钉在最大值"，不是"最大俯仰率"**。这两件事在低速下完全相反：

```
满杆 → 攻角= fcsMaxAOA → 诱导阻力暴涨 → 空速垮到 80 m/s → 升力不够 → 只能下沉
                          ↘ 大坡度下方向舵打满（6°/s 的舵要 30°/s）→ 侧滑滚转力矩 → 机翼左右翻
```

（旧版本这里写的是"criticalAOA 附近副翼变软，ww3 有 controlReversalFactor"。**那是错的**：
`controlReversalFactor` 是"换向时操作面移动得更快"的倍率（su33 = 2.0），不是气动反效。
左右翻的真因是偏航需求超过舵能力后的舵面饱和，见 `docs/ww3-物理基线.md` 3.8。）

日志实证（build109 实机，`latest.log`）：一条 2 分钟的记录里 **18 次全是 `mode=RECOVER`**，速度 74–84 m/s，`cmd p=-1.00`（满拉），`bank` 在 +106° / −112° 之间来回，`vs` 一直 −10…−44。飞机不是"在做机动"，是**在最大攻角上抖翼并持续下沉**；下沉又触发 `RECOVER`，`RECOVER` 又给出 24° 爬升指令，于是满杆再拉一遍——一个自持的豚跳循环。

旧代码里已有 `alphaGuard`，但它的参考量是 `minSpeed`(45)：`(speed − 24.75) / 20.25`，在 65 m/s 以上恒为 1.0，也就是**在任何真实交战速度下都不生效**。中间版本改成按角落速度（corner speed）缩放，`corner = cruiseSpeed × cornerSpeedFrac = 110 m/s`，110 m/s 全权限、82 m/s 只剩 0.43。

**build125 起改成实测攻角**（`useWw3AoaGuard`，默认开）。ww3 自己的攻角一直在那里，只是我们以前只把它写进日志：

```
alphaGuard = clamp((1.30·crit − aoa) / (0.45·crit), aoaGuardFloor, 1.0)     // aoa = 实测攻角
qUp        = min(maxPitchRateUpDeg, plant.pitchRateDeg) × pitchScale × alphaGuard
qDn        = min(maxPitchRateDnDeg, plant.pitchRateDeg) × pitchScale × max(alphaGuard, 0.50)
```

`crit` 是本机型的 `criticalAOA`（su33 **15**、eagle 17），所以同一套参数在两种飞机上给出不同的
边界。它是**软膝**：0.85 倍临界以下全权限，1.3 倍临界削到 `aoaGuardFloor`（0.30）。
速度版本有两个硬伤，这一版就是为了修它们：① 它在 130 m/s 就削权限，而那里机翼离失速还远；
② 它的参考速度 130 高于机体真实极速 103，于是**在任何速度上永久少了约 15% 的俯仰权限**。

两处刻意的不对称：

- **低头权限永不低于 50%。** 攻角高了，唯一能出来的办法是推杆。把推杆也一起按比例削掉，
  等于把飞机锁在高攻角里 —— 这是"越改越坏"的典型写法。
- **没有攻角时自动回落到速度公式**（离线仿真、或某个 ww3 版本不再把数字交出来）。回落路径与
  旧版逐字一致，所以旧测量结果仍然可比。

配套改的还有 `RECOVER` 的爬升角：原来固定 `0.45`（24°），现在按能量分档 —— `≥0.85 cruise` 取 0.45、`≥0.65` 取 0.28、更低取 0.12（约 7°），只有 `agl < minAlt+10` 才强制回到 0.30。**低速改出应该是"平飞加速"，不是"抬头换高度"**：80 m/s 时拉 24° 必然把仅有的能量换光，然后再掉一次。

`status` / `diag` 的日志里新增 `aoa=`（取自 ww3 自己的 `RotationUtils.getPitchAngleOfAttack`），这是唯一能把"正在拼命转"和"攻角已经顶死、副翼失效"区分开的数字。

**偏航需求按机身能力封顶（build122）。** 转弯协调律是 `rDes = g·tanφ / v`，坡度一大它就暴涨：
84 m/s、60° 坡度要 11.7 °/s，77° 要 29 °/s。而 su33 的方向舵只有 **6 °/s** ——
`unshape(需求/能力)` 一旦比值过 1 就**恒定满舵**，满偏舵经侧滑耦合出恒定滚转力矩，且
`tanφ` 在 ±90° 两侧翻符号。于是坡度超过约 28° 之后，方向舵永久满偏、滚转力矩随坡度翻向，
飞机就来回摆。现在需求上限取 `min(maxYawRateDeg, plant.yawMax×0.85)`：舵是协调轴不是操纵轴，
要超过机身能力的量毫无意义。**这是「左右翻」目前唯一有机制证据的解释**（见物理基线 3.8）。

**传感器接线（build125）。** 之前一直说"ww3 不给陀螺/攻角/过载"，那是错的——全量导出
`PhysicsEntity` 之后发现全都有，只是没接。这一版把有收益的接上：

| 量 | 接到哪 | 换掉了什么 |
| --- | --- | --- |
| `localRotVelocity()` | `InnerLoop.setBodyRates()` | 基向量逐帧差分 + `0.08 s` 低通。**那套是自己给自己加的 1.6 tick 相位滞后**，而速率环正是最怕滞后的那个环 |
| `getPitchAngleOfAttack()` | `InnerLoop.setAirData()` | 上面的速度查表（见本节公式） |
| `radioAlt.groundY()` | `Ww3Api.altitudeAgl()` | 只靠 `getEffectiveFloorY()` + 高度图。现在三个来源取**最高**地面（最保守），`hasValidReading()` 为假时忽略 |
| `pullUpAlert.isWarningActive()` | 强制复飞的一个 `||` 条件 | 只靠 `secondsToFloor`。限 `minAlt+150` 以下才信它，否则低空正常飞行会被它一直按在复飞里 |
| `gForce()` | `status` 的 `g=`、日志 | 无（新信息）。用来看"真在转弯"还是"在掉高度"，以及 FCS 有没有在限 G |
| `controlSurfaces.getHandlingAuthority()` | 日志 `srf=` | 无（新信息）。**这条能把"大攻角副翼变软"从猜测变成可观测** |
| `posVelocity()` | `gammaNow` | `getDeltaMovement().scale(20)`（方块/tick ×20）。少一个反复踩的单位坑 |

每一个读都做了 `NaN` 兜底：读不到就退回旧路径，**不是退回零**。

## 三、安装

### 前置

| 项                    | 要求                    |
| -------------------- | --------------------- |
| Minecraft            | 1.20.1                |
| Forge                | 47.4.29（其他 47.x 大多兼容） |
| **ww3**              | 必须，2.1-beta 开发        |
| **Distant Horizons** | 必须（ww3 的硬依赖）          |

### 步骤

1. 把 `ww3ai-1.0.0.jar` 放进 `.minecraft/mods/`。
2. 确认 `ww3` 与 `distanthorizons` 也在 `mods/` 里。
3. 启动游戏，主菜单 → Mods 列表能看到 "WW3 Air Combat AI" 即安装成功。
4. 单人游戏请**开启作弊**（Esc → 对局域网开放 → 允许作弊），否则 `/ww3ai` 命令会被权限拦下。

> 专用服务器：`/ww3ai` 全部子命令需要 OP（权限等级 2）。菜单里涉及世界状态的按钮默认也要求 OP，可用 `general.menuRequireOp=false` 放开。

## 四、五分钟上手

最短路径，从零到看见飞机自己打架：

```
① /ww3ai deployer            → 拿到「空战部署器」
② 手持部署器右键             → 打开部署器界面
③ 机型 < >  选 f15e
   队伍 < >  选 red（列表里没有就先点「新建」→ 填 red → 「建队」）
   高度      填 150（相对地面）
   AI驾驶    点一下按钮，让它显示「AI驾驶: 开」
④ 点「下一步 →」              → 地图上点一个位置
⑤ 点「投放（AI 驾驶）」        → 飞机在该点上方出现，AI 立即接管
⑥ 按 G 打开控制台            → 点「生成友机」，看它们互相咬尾
⑦ /ww3ai status              → 确认 tracked=2，说明两架都被接管了
```

> **「AI驾驶: 关」是停放模式**：飞机会被放在地面上、油门归零，AI 不会碰它，走过去上机就能自己开。
> 想给 AI 用就必须打开这个开关；关着的时候，即使填了 150 的高度也只当"放在地上"。
>
> 源码默认 AI 只把**玩家**当目标（`targetPlayersOnly=true`）。**当前实例（`1.20.1-forge-47.4.29/config/ww3ai-common.toml`）已改成 `false`**：双方僚机都能把对方的飞机实体纳入目标池、互相交战；改回 `true` 就退回「只打玩家」。另一个前提是双方飞机确实处在敌对阵营（`canEngage` 才放行），控制台里点「敌」分好队伍。

## 五、两个入口

### 1. 控制台（按 `G`）

管理"世界状态"，不涉及具体某一架飞机。

| 区域   | 能做什么                                                             |
| ---- | ---------------------------------------------------------------- |
| 载具列表 | 每行显示一架附近载具，右侧按钮：`敌` `中` `友` 设我方队与该队关系、`入队` 玩家加入该队、`分派` 入队、`删` 删除（需二次确认） |
| 底部左侧 | `阵营: 敌军/友军/按 ww3 关系`、`AI: 开/关`、`开火: 允许/禁止`                       |
| 底部右侧 | `一键配置友/敌`、`模型接入`、`编队队形`                                       |
| 新建队伍 | 底部分页行下方固定一行输入框 + `新建队伍`；名字合法即建队（1–16 字符，可中文），建完可 `分派` |
| 最底栏  | `生成友机`、`生成敌机`、`上机`、`清场`、`全部敌对`、`全部结盟`、`刷新`、`关闭`                            |

`清场` 是**一键清除所有战机**：第一次点是待确认态（按钮变红字 `确认清场`，5 秒内不点自动撤销），第二次点才真正执行，等价于 `/ww3ai clear`。

生成按钮有 20 tick 冷却、160 格内 32 架的软上限，按住不放不会刷爆服务端。生成的飞机会**继承你手持部署器的 AI 选择**——拿着绑了模型的部署器点生成，出来的就是模型机。

### 2. 部署器（手持物品）

管理"这一架飞机怎么配、投在哪"。右键打开，或潜行+右键方块快速按预设投放。

三步流程：

```
[配置] 机型 / 队伍 / 高度 / 航向 / 武备 / AI  →  [选点] 地图点位置  →  [投放]
```

| 控件            | 说明                                     |
| ------------- | -------------------------------------- |
| `机型 < >`      | 循环切换 ww3 全部机型                          |
| `队伍 < >`      | 投放后自动加入的队伍                             |
| `新建`          | 就地建队：点开后填名字 → `建队`，成功后自动选中该队（新世界不必先建队）  |
| `高度` + 模式按钮   | 默认 120 格，相对地面（AGL）或绝对高度（Y），点按钮切换模式     |
| `航向` + `±15°` | 默认 90°（正东），可用按钮微调或直接输入                 |
| `武备/蓝图`       | 进入挂架配置页（见下节）                           |
| `AI驾驶: 开/关`   | **开**＝高空投放并由 AI 起飞作战；**关**＝放在地面上待机，AI 不接管，留给你自己开 |
| `保存预设`        | 把当前配置写进物品 NBT，下次掏出还是这套                 |
| `下一步 →`       | 进入地图，点选投放点，可手动改 X/Z                    |
| `地图 - / +`     | `+` 放大（看得更细）、`-` 缩小（看得更远），与滚轮同向；最小 ±32 格、最大 = 最大投放距离 ×1.15 |
| `全图`          | 一次缩到能看下整个合法投放半径（绿圈就是它）                |
| `投放（AI 驾驶 / 停放自用）` | 按钮文字就是本次投放的结果；服务端校验距离（默认 ≤2000 格）、离地净空（AI 驾驶 ≥120 格 / 停放 ≥40 格）、权限后才生成 |

**AI 驾驶投放最低 120 格（离地）**，`停放(自用)` 仍然是贴地 1 格。原因不是"保险"，是物理：空投给出的是 **70 m/s + 20° 仰角**，5 秒内速度会掉到 78 m/s；而 60 格正好等于强制改出地板 `minAltitudeAgl`，飞机在这条线上起手就进 `RECOVER`，低能量时改出只卸载不爬升，出不来——`latest.log` 里曾连续记录三分钟 `mode=RECOVER agl=0 spd=74`，那架僚机全程没飞到编队位置。

> **2026-11-14 更正**：过去这里写"74 m/s 时抬头权限只有 27%"，那是错的——27% 是我们自己 `alphaGuard` 软膝算出来的，ww3 在 40 m/s 以上操纵权限本来就是满的。同一批日志里 `agl=0` 的主因也不是真飞得低，而是**高度读数塌成 0**（ww3 的地板钳位 + 我们自己的无线电高度表交叉校验），已在 build131 修复，见 §十三 的「假 AGL=0」排障行与 §十四 的边界说明。120 格净空仍然保留，作为不依赖高度读数的独立保险。

低于这个高度时服务端直接拒绝并报出当前高度，不会静默“帮你抬到 120”。改这个下限用 `deployer.aiMinClearance`（默认 120，范围 40–280）。

**地图是可缩放的**：左上角标签 `±128 格 上限 2000` 是"当前半宽 / 服务端允许的最大半径"。缩放只改投影、不移动已选点——点位存的是世界坐标，放大缩小后十字准星还钉在原处。缩到能看见**绿圈**时，**圈内才是能投的**（服务端判的是直线距离，所以画的是圆而不是方框；地图非正方，屏幕上看着是椭圆）；点超出范围时十字变橙、右侧「距你」标红并加 `超限`，服务端也会拒。缩得太小时 32×32 网格每个格子代表几十格，地形只能看出大概走向，这就是"战略视图"的代价。

**校验都在服务端**：客户端界面只是提建议，改客户端也投不出违规坐标。

## 六、武备与蓝图

部署器界面点 `武备/蓝图` 进入，标题为「WW3 武备与蓝图」。

1. **选挂架**：左栏列出该机型的全部挂点（`Station`，多页时用 `挂点 1/N` + `<页` `页>` 翻页），点选后右栏出现该挂点可用的武器/吊舱。
2. **选弹种**：每个挂点一行，左右 `<` `>` 循环。`默认` 表示沿用 ww3 原始配置。
3. **选 AI**：左栏 `AI: 预设脚本` 一行，用两侧 `<` `>` 切换。选项 = `预设脚本` + 所有已启用渠道下的所有模型。这就是"这架飞机用哪个大脑"。
4. **存蓝图**：右下填名字 → `保存`。蓝图存在**存档**里（`data/ww3ai_blueprints.dat`），同存档的所有部署器共享。同名时按钮变 `确认覆盖`。
5. **应用**：`应用并返回` 写回手持部署器并回到上一页，投放时生效。只想还原挂载用 `恢复默认`。

蓝图里同时记录了机型、每个挂点的选择、以及 AI 绑定。所以"F-15E 反舰挂载 + DeepSeek"可以存成一条，下次一键还原。

> 注意：武备预设只存在于**物品 NBT**。切换快捷栏导致手上没有部署器时点「应用」会明确报错「请手持部署器」，不会假成功。

### 雷达锁定与导弹

AI 的雷达是自动的，不用你操作：

- **开机**：接管时若雷达开关是关的就打开（`[weapons] enableRadar`）。
- **锁定**：每 4 tick 把锁定放在 `pickTarget` 选中的那**一架**上（`enableRadarLock`）。雷达接触本身按 ww3 的 `ServerTeam.canEngage()` 过滤，只接受 ENEMY / NEUTRAL，所以不会去锁友军。
- **导弹能不能打，不是我们决定的**：ww3 的 `WeaponGroupState.canBeFired()` 要求导弹的**动态发射区（DLZ）**判定"目标在区内"，而 DLZ 是对**锁定接触**算的。没锁 = 只能打机炮。这也是 `/ww3ai status` 里 `lk=` 这一列存在的意义。
- **几何**：导弹要求机头指向误差 ≤ `missileConeDeg`(25°)、距离 ≥ `missileMinRange`(250 m)；机炮是 6° 锥、30 m 起。距离超过 `missileRangeHint`(350 m) 时优先选带发射区的武器组，否则用机炮。
- **你会看到什么**：被 AI 锁定时，你自己的 RWR 会响——这是正常的，说明它的雷达确实照着你。

已知限制（物理，不是 bug）：半主动雷达弹需要载机持续照射，AI 发射后如果立刻大角度转走，弹会丢；目前没有"发射后保持照射"的专门逻辑。

### 红外弹（热寻的）

红外弹和雷达弹是两套完全不同的规则，AI 对两者都做了适配：

| | 雷达弹（AIM-120 / R-77） | 红外弹（AIM-9M/9X、R-73、FIM-92） |
| --- | --- | --- |
| 发射前要不要雷达锁 | **要**，DLZ 是对锁定接触算的 | **不要**。`dlzProvider.mustBeInZoneToFire=false`，只看扳机 + 冷却 + 余弹 |
| 导引头视场 | 由雷达弹自身导引头决定 | 外框 10°、内框 5–7°；9M 离轴 40°，9X/R-73 可达 80–90° |
| 有效距离 | 远（几十公里） | 外框 1300 m（9M）/ 2000 m（9X、R-73）/ 1500 m（毒刺），**内框 70 m 内不衰减** |
| 被干扰 | 靠 chaff / notch | 靠 **flare**：每 tick 有 2–3% 概率重选目标（`decoyChance`） |

AI 侧的关键一步是**发射后补锁**（`[weapons] irHandoff`）：

- 无人机的 IR 武器组没有"使用者"。ww3 的 `InfraredMissileGroupState.tick()` 在这种情况下**每 tick 把 `lockedTargetID` 清成 -1**，于是 `onSpawnWeapon` 拿不到锁定，导弹只能靠自己 10° 的导引头去找目标。而 AI 的发射锥是 25°——等于把弹打进了导引头看不见的地方。
- 所以每 tick 扫一遍本机 64 m 内新出现、还没锁目标的红外弹，直接 `setInitialLock(打的那架飞机)`。这会调 `forceLock`，把导引头光轴直接钉在目标上，之后只要目标还在离轴包线内就能一直跟住。
- `/ww3ai status` 里的 `ir=` 就是这个补锁计数。首次补锁会在日志打一行 `IR hand-off #1: f15e -> <目标>`。

**为什么打 flare 的目标经常脱靶**：这不是 AI 的问题，是 ww3 的数值。`FlareEntity` 的热信号常量 1.2，战斗机 `heatSignatureMultiplier` 是 1.0（A-10/AV-8B 0.75）。弹在飞行中每 tick 有 2–3% 概率重评目标，一旦 flare 落在 3–4° 的 `decoyFovDegrees` 内且视线可见，热量更高的 flare 就会把锁抢走——加上距离衰减，800 m 外几乎必被吸走。想让红外弹更硬，改的是内容包里的 `decoyChance`/`decoyFovDegrees`，不是 AI。

### 导弹发射节奏：一次一发，两秒间隔

ww3 的导弹组**一次扳机只放一枚**（内部是 `NextToFirePylonHandler`，按挂架轮转）。所以"一下子全射出来"不是 ww3 的行为，是**扳机节奏**的问题：原来开火间隔是 `fireIntervalTicks=2`，扳机按下、两 tick 后松开、再两 tick 又按下——4 枚弹在约 0.4 秒内全部离架。看起来是一次齐射，也顺带把每一枚弹本该有的"决定"都省掉了。

现在导弹单独用一个间隔键：

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `[weapons] fireIntervalTicks` | 2 | 机炮的点射间隔（10 发/秒，维持原来的短点射手感） |
| `[weapons] missileSalvoGapTicks` | 40（2 秒） | 两次**导弹**发射之间的最短间隔 |

2 秒的含义是：打出一枚之后，它必须把目标重新保持在 25° 锥角和射程带里整整一个再攻击周期，才能打第二枚。这就是导弹"有博弈"的来源——每发都是当时的几何判断，而不是一次把挂架清空。

每次发射都会打一行日志，带前后弹药数：

```
[ww3ai] f15e missile away at 820m, ammo 6 -> 5
```

如果 `ammo` 一次掉 2 以上，说明这一发是 `isMultiMode` 的组（ww3 允许双联装同时放），把 `missileSalvoGapTicks` 调大并不能解决，需要在挂载配置里改组；日志会把这个情况直接暴露出来。

**关于太阳**：白天太阳也是合法热源（`SUN_TARGET_ID=-2`，距离按 10000 m 算）。机头朝着太阳方向打弹，导引头可能锁到太阳上——ww3 玩家也会遇到，属原版行为。

### 编队与目标分配

#### 队伍分配：只有「我方」和「敌方」（build132 起）

所有生成入口现在只说**意图**，队名由 `TeamPolicy` 一处决定，不再有菜单「我方队伍」指针、不再有第三套队名（旧的 `ww3ai_opfor`）：

| | 队伍 | 规则 |
|---|---|---|
| 我方 | 你当前真实所在的队 | 无队时自动加入 `[teams] playerTeam`（默认 `blue`）；你换队，我方队跟着换 |
| 敌方 | `[teams] aiTeam`（默认 `red`） | 与你的队同名时自动换成不冲突的名字 |
| 关系 | 我方 ↔ 敌方 | 生成敌机时自动确保 `ENEMY`，避免 ww3 判 NEUTRAL 让敌机混进友军编队 |

| 入口 | 意图 |
|---|---|
| 菜单「生成友机」/ `/ww3ai spawn` | 我方（僚机，直接进编队） |
| 菜单「生成敌机」/ 部署器默认队伍 / `/ww3ai hostile` / `prepare` | 敌方 |
| `/ww3ai assign`（不带参数） | 把附近飞机分到我方 |

菜单每行的「入队」= 玩家加入该队，该队立刻成为我方队；`敌 / 中 / 友` 改的是我方队与该队的关系。**「玩家无队 → 同队过滤自动跳过」这条降级路径已删除**：`wingmenSameTeamOnly=false` 是唯一关闭过滤的方式。


生成两架以上飞机时，它们不再是各飞各的，而是先编成**一个 section**。

#### 谁算僚机：只认你所在的队（`[formation] wingmenSameTeamOnly`）

默认 `true`：**和你同属一个 ww3 队伍的 AI 飞机才是你的僚机**（雷达上青蓝 `OWN` 的点），才会拿 `W1`/`W2` 槽位、跟着你飞楔形。判据是**玩家本人当前的队伍**，由 `TeamPolicy` 统一解析。

- 盟友队（`ALLY`，绿色）、中立（白色）、没入队的飞机：AI 照常驾驶，但**独立飞行**，不进你的编队；也不会因此变成靶子（`friendIds` 仍把它们算友方，避免 `engageNeutral` 时误伤自己投放的飞机）。
- 敌方（`ENEMY`，红色）：照旧组成独立的敌方机队。
- **你没加入任何队伍时，模组会自动把你加入默认队**（`[teams] playerTeam`，默认 `blue`），并在 `latest.log` 打一条 `auto joined`；同队过滤照常生效，不再有静默降级。
- 想回到旧行为（所有非敌机挤进一个大编队）：把 `wingmenSameTeamOnly` 设成 `false`。

**一步到位**：`/ww3ai assign`（不带参数）把附近所有飞机分到**你当前所在的队**，它们立刻成为僚机；`/ww3ai assign <队伍>` 仍是指定队伍。「生成友机」和 `/ww3ai spawn` 默认就进这个队。

`logs/latest.log` 的 `section formed` 行现在带 `wingTeam=... offTeam=N`，`/ww3ai status` 多一行 `wingmen: team=... sameTeam=N offTeam=N rule=...`。**排查「没形成编队」先看这一行**：`offTeam` 不为 0 就说明有飞机在别的队；`rule=any non-enemy` 只可能是 `wingmenSameTeamOnly=false`，不再由「玩家无队」触发。

#### 你自己当长机（硬规则）

只要你正坐在一架 ww3 飞机里，**你的飞机就是长机**，AI 全部是僚机。这是**无条件的不变式，没有配置开关**：`playerLeads` 键已删除，旧版把它设成 `false` 时，你的座机会被移出候选又被漏加进 section，结果一架 AI 机在给一支「不含你」的编队带队。`enableFormation` 只决定僚机**是否飞槽位**，永远不改变谁是长机。

判断依据只有一条：玩家实体 `getRootVehicle()` 是一架 ww3 飞机（固定翼或直升机）且还活着。`/ww3ai status` 即使只有你一架，也会显示 `section: 1 aircraft, leader ... (you)`；**没有 `(you)` 就说明座舱没被识别**（坐在地面载具、非驾驶位失效、或刚上机还没过下一个控制周期）。

- AI **不会碰你的操控**。它只读你的位置、航迹方向和速度作为队形基准，输入永远不写进你的飞机。
- 你坐的那架飞机也**不会被 AI 接管**，即使 `takeoverTaggedOnly=false`。
- 你的飞机会被标成"友军"，任何情况下 AI 都不会把它当目标——即使 ww3 把你的无人座机判成 NEUTRAL。
- 僚机编号和位置照旧（W1 左、W2 右……），只是基准从"最近的 AI 机"换成了你。

你下机或改成开别的载具，长机自动交回 AI，日志会重新打一次 `section formed`。

要让 AI 有僚机可用：`/ww3ai spawn su33` 生成几架（会自动打上 AI 标记），或者用部署器放置后 `/ww3ai adopt`。

**跟得紧不紧**：僚机只在 `wingEngageRadius`(700 m) 以内有敌机时才脱离编队交战。远处出现目标不会让机队四散——否则"僚机"立刻变回三架各飞各的飞机。把它设大（或 0 = 不限）就是"看见就打"，设小就是"死跟着我"。

**低空**：僚机的触地保护地板在编队状态下降到 `formationFloorAgl`(40 m)，因为你会贴着山谷飞。否则它每几秒就判定"太低"而强制爬升离队——编队保持和强制恢复不可能同时成立。

#### 谁当长机（AI 自己编队时）

没有玩家在飞的情况下，长机是机队里离你最近的那架（已经在朝战斗方向飞）。长机一旦选定就**不随距离变化换人**——机队每 tick 按距离重排，如果谁近谁当长机，转弯中途换长机就会让全队互相穿插。只有长机消失才重选。

#### 僚机站哪（极坐标：半径 + 夹角）

队形用**极坐标**描述，四个数：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `formationRadius` | 75 m | 1 号席位离长机多远 |
| `formationRankStep` | 75 m | 每往后一排再加多远（第 r 排 = radius + (r−1)×step） |
| `formationHalfAngleDeg` | 53.1° | 半角，从长机**正后方**量起；0° = 全部在尾流一条线上，90° = 横队 |
| `formationDroopDeg` | 6.1° | 每排比长机低多少（角度，正 = 更低） |

奇数席位在左（−半角），偶数席位在右（+半角）。默认值算出来的就是老的那套梯队：

| 席位 | 相对长机 |
| --- | --- |
| W1 | 左 60 m，后 45 m，低 8 m |
| W2 | 右 60 m，后 45 m，低 8 m |
| W3 / W4 | 上述偏移的 2 倍（半径 150 m） |

偏移定义在长机的**航迹坐标系**里：`前` = 长机速度方向，`右` = 该方向与世界上方的叉积（永远是水平的），`上` = 右 × 前。

这既不是世界坐标也不是机体坐标，两者都有坑：

- **世界坐标**：你一转弯，僚机就朝固定罗盘方向飞，队形立刻散掉。
- **机体坐标**（最早的做法）：槽位会跟着你的**滚转**转。你倒扣时"左 60 m、低 8 m"两个偏移直接对调，僚机被要求在瞬间横向平移 120 m——实测就是一个完整横滚让槽位跳 120 m，僚机只能猛拉杆去追，看起来像疯了一样。真实的编队不会这样：僚机保持的是相对你**航迹**的位置，你滚你的。

换成航迹系后，同样一次 180° 横滚，槽位位移是 **0 m**；转弯和爬升照旧跟着走。

#### 可视化改队形：J 键 / `/ww3ai formation`

按键 **J**（可在「控制 → 按键」里改），或控制台（G）右下角的**「编队队形」**按钮，或命令 `/ww3ai formation`。三个入口发的是同一个请求，界面也一样。

界面左边是两张图，右边是滑杆：

- **俯视图**：长机是中间的白菱形，`前` 朝上，僚机是身后的方块，琥珀色的 1/2 号是**可拖的把手**，直接拖它就同时改了半径和半角。虚线圆是 1 号席位的半径、暗一点的圆是第 2 排，黄色圆弧就是半角。图上显示的一直是**草稿**，也就是你按下「应用」之后真会飞的形状——它和飞机用的是同一个 `FormationMath.slotOffset(...)`，不是另画一份。
- **侧视图**：纵向拉开看谁比谁低（下沉角），否则 200 m 队形里的 8 m 落差只有一个像素。
- **滑杆**：半径 / 外扩 / 半角 / 下沉 / 气泡 / 汇合，以及「席位」「走廊」两个开关。
- **预设**：梯队（默认）／楔形／横队／纵队，一键填四个数。

下面的读数把极坐标翻译成能对得上日志和老文档的横／后／下，并会给两种会出事的情况标红：

- `外扩=0`：第 2 排和第 1 排落在同一圈上。
- 同排间隔小于分离气泡（默认 40 m）：两架僚机会在同一个点上互相顶。

**「应用」之前什么都不发**。拖拽只在本地改草稿（每像素发一个包会每像素重写一次 toml，而且"应用了一半"的队形根本不是一个队形），按「应用」才一次性提交、写进 `config/ww3ai-common.toml`、下一 tick 生效。「恢复默认」回到出厂四个数。

改形状不会重建席位：`fm=W1` 还是 W1，只是它站的位置变了。队形刚改完的那一两秒，正在站位上的僚机会平移过去——**改大半径时不要贴着地面做**。

位置保持做了两件事，否则僚机会像追尾巴的狗：

- **前馈**：飞向"槽位 0.7 秒后的位置"（`formationLeadSeconds`）。一阶航向环追一个 130 m/s 移动的点必然有滞后；加 0.7 s 前馈后 30° 盘旋的稳态误差约 60 m 且不发散，加到 1.0 s 就会过冲。
- **近距混合**：离槽位近（<150 m）时按长机航向飞，远时直接朝槽位追。纯追槽位的话，一旦冲过头会发现槽位在身后，然后掉头 180° 回来。

速度用油门匹配长机，不用机头——用机头追速度会变成"低头加速 → 冲过头 → 抬头减速"的锯齿。

具体是**串级**，不是直接把"位置误差"接到油门：

```
vCmd     = 长机速度 + clamp(沿航迹误差 × 0.25, -15, +25)   // 位置误差 -> 想要的速度
throttle = clamp(0.55 + (vCmd - 本机速度) × 0.06, 0.10, 1.0)  // 速度差 -> 油门
```

这样闭环里有两个环节（位置→速度、速度→油门），速度指令被 `±15/+25` 限住，就不会出现"落后 300 m 就百分百油门、冲过头再关到 10%"的极限环。这一条是离线仿真 S7 逼出来的：旧的一步到位油门律（位置误差直接乘 0.0015 加到油门）在同场景里稳态误差 **290 m 且永远进不了 100 m**，改成串级后是 **41 m / 37 秒到位**。

#### 槽位是"座位"，不是"排队号"（`[formation] formationSlotSticky`）

僚机编号（W1/W2/W3…）是**席位**，只要它还在这个 section 里就一直保留，别人加入或阵亡都不会让它换号。默认 `true`。

旧做法是每 tick 把僚机按 UUID 排序后发 1..N 号。看起来等价，实际上不是：**只要掉一架（被击落、进 RECOVER、被分到别的队），后面的僚机全部前移一位**。而奇数号在左、偶数号在右——W2 变成 W1 不是"补上空位"，是要求它从长机右侧 60 m 横穿到左侧 60 m，**平移 120 m 而且是从长机尾流里穿过去**。空中看到的就是"编队自己炸了"。

离线仿真 S7 的同一场景（击落 W1 后看 W2）：旧逻辑 `2->1 (+120 m)`，席位制 `2->2 (kept)`；稳态站位误差同时从 74 m 降到 41 m。

新加入的僚机拿**当前最小空号**，不会因为"队伍只剩 2 架"而被发到 W7。

#### 分离气泡（`[formation] formationSeparationBubble`，默认 40 m）

槽位偏移只说明"到位之后间距多少"，管不了**归队路径**。两架从两侧同时归队的僚机会在空中交叉，贴着长机尾巴滑进槽位的僚机会以 100 m/s 从长机身边掠过——这两件事在站位误差指标里都看不出来，只看得到撞机。

所以在 40 m 以内，每架僚机会按距离成比例地被推离邻居（只推机头方向，**绝不动油门**：同时减速的两架只会互相追尾），推力的垂直分量被刻意去掉——侧向规避是机动，往下躲是找地面。

#### 归队走廊（`[formation] formationRejoinCorridor`，默认 **false**）

`true` 时，离槽位超过 `formationJoinRange`(600 m) 的僚机不再直冲槽位（那等于朝着长机侧前方 60 m 的一个点飞，横穿长机机头），而是先飞到长机**正后方的汇合点**（保持自己的横向偏移、`formationRejoinBack`(300 m) 之后），最后一段顺着自己的横线滑进槽位。

**默认关**，因为有测量：S7 里开启后稳态站位误差 131 m，关闭时 41 m（入口 700 m、四机同速条件下）。它只在"从 1.5 km 外归队"这种场合才有价值，而离线仿真跑不出那个条件（僚机对长机没有速度优势，追 1.5 km 要几分钟）。要用就自己打开，并观察 `/ww3ai status` 里 `fm=` 是否还在 `W1/W2`。

**什么时候散开**：僚机一旦有目标就立刻放弃站位去交战（站位只在 `PATROL` 分支生效）。编队保持会一直把飞机拽回长机后方，带着这个约束是打不了仗的。

**目标分配**（`[formation] enableTargetAssignment`）：每 40 tick 把"哪架打哪个目标"当成一个整体来解，而不是每架各挑最近的。

- 代价 = 距离 + 偏离机头角度 × `assignmentAngleWeight`(6 m/度)，所以正前方的目标比略近但需要掉头的目标更优先。
- 用**匈牙利算法**求全局最优匹配（MIT 的 `or-assignment-problem` 同一套公式，这里重写并支持非方阵）。3 打 2 时不会出现"两架抢一个、另一架没人管"。
- 目标列按 `maxAttackersPerTarget`(2) 复制，所以配额是天然的一对一：默认允许双机攻击一个目标（长机/僚机战术），第 3 架留作高空掩护。
- **你的飞机不参与分配**（给人类摇杆派目标没有意义），但你**雷达锁住的那架会被扣掉一个攻击席位**，所以僚机会铺开到别的目标上，而不是全挤在你正在打的那架后面。
- 没有分到目标的飞机保持编队——这就是二机编队只有一架敌机时的正常表现，不是摸鱼。

`/ww3ai status` 第一行是 section 摘要，例如你在当长机：

```
section: 3 aircraft, leader f15e/1a2b3c4d (you), 2 assigned
f15e/5e6f7a8b PURSUE  tgt  lk=yes ... fm=W1
f15e/9c0d1e2f PATROL  -    lk=no  ... fm=W2
```

`(you)` 表示长机是你。`fm=` 是站位：`L` 长机、`W1`/`W2` 僚机编号。

**现在没做的**：数据链共享雷达接触（每架还是用自己的雷达锁）、交叉掩护/轮流攻击的显式规则、导弹来袭告警与规避、僚机主动替你挡/解围。编队是"站位 + 分配"，不是完整的四机战术。

## 七、编队战术：集中 / 分散 / 保护

编队之前只有一种打法：匈牙利分配把全队摊到不同目标上，谁也没法下令"一起打那架"或者"别追了回来护着我"。现在机队有三种状态，对齐《皇牌空战》里的僚机指令。

### 一个键切三态

游戏里按 **`H`** 循环：

```
分散猎杀 SPLIT  →  保护长机 GUARD  →  集中火力 FOCUS  →  分散猎杀 …
```

每次按键在动作栏报当前战术（`[ww3ai] 僚机战术: 集中火力 (focus)`）。**状态由服务端保管**，客户端只发"下一个"，所以掉包、连按、多人同时按都不会让动作栏和实际行为对不上。按键可在「选项 → 控制 → WW3 空战 AI」里改绑；`G` 仍然是打开控制台。

不想用按键也能下令：`/ww3ai section` 查看，`/ww3ai section focus|split|guard` 直接设。默认 **SPLIT**，也就是加入这个功能之前的原始手感。

### 三态到底改了什么

| 状态 | 目标分配 | 站位 | 什么时候用 |
| --- | --- | --- | --- |
| **FOCUS** 集中火力 | 目标池只留**长机正在打的那架**（没锁定时取离长机最近的），配额放开到全队数 | 允许脱离，各打各的进入角 | 一架硬目标、需要快速打掉；或者长机咬住了但自己火力不够 |
| **SPLIT** 分散猎杀 | 原样：`maxAttackersPerTarget`(2) 配额下的匈牙利全局最优 | 各自自由 | 目标数量和我方相当，避免互相挡射界 |
| **GUARD** 保护长机 | **只打威胁长机的目标**：距长机 < 800 m，或朝长机接近率 > 50 m/s | 收紧在长机周边，超 400 m 强制放弃目标回长机（有编队时回槽位） | 长机被咬、你在带人撤、或者有需要护着的载具 |

`GUARD` 有两道闸门，缺一不可：分配器把接触过滤成"威胁"，另外每 tick 在目标解析完之后再硬判一次 —— 因为没分到目标的僚机会退回"打我能打的最近那个"，那正好是保护模式要禁止的。超出 `guardLeashRadius`(400 m) 的僚机直接被当成无目标，走 `PATROL` 回站位，扳机也一起松开。

牵绳是**独立特性，不依赖 `enableFormation`**：编队开着时僚机回槽位，关掉编队时 `PATROL` 直接朝长机（牵绳点）飞回，不会原地打转。长机本身是基准，不受牵绳约束。

`FOCUS` 下**长机锁定的目标不再扣掉一个攻击席位**，反而把全队都派上去——这和 SPLIT 的处理正好相反。如果长机什么都没锁，就取离长机最近的接触作为集火点。

### 敌方机队自己判断

敌方队伍不是你控制的，它每 `enemyOrderIntervalTicks`(100 tick = 5 s) 自己评估一次，规则是三条：

1. **他们长机被咬** → 立刻 `GUARD`（我方飞机在距其长机 700 m 内，或朝其长机接近率 > 40 m/s 且距离 < 1200 m）。接近率按 **m/s** 计算，与 `guardThreatClosure` 同一量纲。防御转换不等迟滞，等 10 秒长机早没了。
2. **他们数量不亏且我方还有人** → `FOCUS`，集中吃一架。
3. **他们数量劣势或没有威胁** → `SPLIT`，散开免得被一波带走。

非紧急的切换要连续 `enemyOrderAgree`(2) 次评估一致才生效，否则队伍会在阈值附近每 5 秒抖一次，什么战术都执行不完。

**谁是"敌方队伍"**：用 ww3 自己的 `coalition` 判定（和扳机用的是同一套），玩家坐飞机时以座机为基准，徒步时以玩家实体为基准。被判为敌对的 AI 飞机不再挤进你的编队——以前它们会按距离排进 `section`，等于把敌人挂到你的僚机位上。敌机之间也互不攻击。

敌方 `GUARD` 时僚机会围着**他们自己的长机**站位并受一条更长的牵绳（640 m）；`FOCUS` 时全队一起压我方长机。敌方的 `targetPlayersOnly` 限制会放宽，否则"集中打我方长机"这种指派会被过滤掉（默认该配置是 `true`，而指派对象是飞机实体不是玩家实体）。

调试用：`/ww3ai section enemy focus|split|guard` 把敌方战术钉住做对照，`/ww3ai section enemy auto` 恢复 AI 判断。

### 看状态

`/ww3ai status` 前两行：

```
section: 3 aircraft, leader f15e/1a2b3c4d (you), 2 assigned, order guard (保护长机)
enemy section: 2 aircraft, order focus (集中火力)
```

第一行的架数只算**我方**机队（玩家算 1 架，敌机不计）；敌方架数在第二行单独列出，两行不重复计数。

### 边界

- **FOCUS 会挤射界**：全队同航向压一个目标，前机挡后机，红外弹还会抢同一个热源、被一发热焰弹一起骗掉。现在没有做进入角错开，也没限制"只有最近的一架发弹"。三机集火时留意 `ir=` 和 `shots=`。
- **GUARD 和主动进攻是冲突的**：你自己冲进缠斗时，僚机会被 400 m 牵绳拽在后面。想让它们跟上来就切 FOCUS/SPLIT，或把 `guardLeashRadius` 调大。
- 分组依赖 `coalition`：无队伍的无人机会被判 `NEUTRAL`，不会被当作敌方队伍成员；这种飞机仍按原来的逻辑处理。
- 敌方战术是**确定性规则**，不是大模型决策：它按全队每 5 秒跑一次，模型延迟在这里只会坏事。

## 八、追踪几何与机动

这一节是**内环之上、决策之下**的一层：决定"机头往哪指"，但不碰杆量。以前这一步只有一个公式——`目标位置 + 目标速度 × 0.6 秒`，也就是对任何情况都用提前追踪。

### 三段追踪律

BFM 里追踪分三种，选错的那两种就是"打不着"和"冲过头"：

| 几何 | 瞄哪 | 什么时候用 | 为什么 |
| --- | --- | --- | --- |
| **LEAD** 提前 | 目标前方 | 远距接近、目标横穿 | 缩短进入时间 |
| **PURE** 纯追踪 | 目标本身 | 目标在急转（>25°/s） | 提前点根本追不上它的转弯圆 |
| **LAG** 滞后 | 目标**后方** | 身后追击、接近率过大 | 把多余速度花在更宽的弧线上，保住"在它后面" |

判据按优先级：先看要不要 LAG（在它后面 + 距离 < 700 m + 接近率 > 150 m/s），再看要不要 PURE，剩下才 LEAD。

两个容易写错的地方，这里都踩过：

- **提前量必须按视线的垂直分量算，不能按接近率算。** 目标直线逃跑时接近率很大但横向速度为 0，正确的提前量是**零**；按 `距离/接近率` 算会给出 2 秒、200 多米的提前量，机头偏 30° 以上——比原来那个固定的 0.6 秒还差。现在只用目标速度垂直于视线的分量，再按 `leadGain`(0.6) 缩放、限制在 `leadAngleTan`(0.5，约 27°) 以内。
- **LAG 必须同时压油门**（`lagThrottle` 0.70）。只把机头指向目标后方而油门照给，接近率一点没变，冲过头只是晚一秒。

`/ww3ai status` 里的 `pur=` 就是当前用的哪一段，例如 `pur=LAG-0.7`。

### 起落架：它为什么以前永远只有 75 m/s

ww3 构造载具时**起落架是放下的**（`LandingGearHandler` 的初始状态就是 down），而这个模组从来没有把它收起来过。一架 20 t 战斗机挂着起落架飞完整个航程，多出来的寄生阻力足以把速度钉死在 75 m/s 附近——于是它永远在"低速 → 攻角顶死 → 下沉 → 强制改出 → 再低速"的闭环里。这曾经被当成失速、被当成攻角限制、被当成 `recover` 门限太保守，连续三轮都改错了地方。

现在：

- 接管第一 tick 就 `setIsDown(false)`，日志打 `gear up (was down at takeover)`；
- 每 5 秒复查一次（受伤、读档都可能让它重新放下）；
- 受 `canBeRaised()` 约束：真正停在地面时不会硬收；
- `gear=up / DOWN / moving` 出现在 `diag` 与 `sinking:` 行里，任何"没速度"的问题先看这三个值。

如果你的存档里已经有一批飞机是挂架状态飞着的，重启后它们会在接管时自动收起，不需要重新生成。

### 攻击地板：它为什么以前"点一下就掉头"

一个往下追的攻击命令要穿过三道闸，任何一道说不行就转 `EXTEND`（掉头爬走）。历史上这三道的松紧严重不匹配，结果就是"俯冲进入 → 一秒后改出 → 爬回去"的循环：

| 层 | 判据 | 默认值 | 性质 |
| --- | --- | --- | --- |
| 俯冲地板 | 瞄准点最低压成 17° 俯角（低于 `minAlt+140`） | 固定 | 几何，预测性 |
| 强制改出 `recover` | 按当前下沉率算，**还剩几秒触地** < `recoverSeconds` | 2.2 s | 能量，预测性 |
| 攻击硬地板 | 瞄准点在下方 **且** `agl < minAlt+45` | 105 m | 位置，兜底 |

改之前是：`tooLowToDive = 瞄准点在下方 && agl < minAlt+120`（即 180 m），外加 `recover` 硬编码 3.5 秒。两个问题叠加：

- **几何判据在低空恒定成立**。你飞在它下方时，瞄准点"在下方"是定义上必然的，所以它在 180 m 就无条件脱离——不是判断危险，而是在拒绝俯视任何东西。
- **3.5 秒的改出门比攻击门还高**。150 m/s、17° 俯冲 = 44 m/s 下沉，`(agl−60)/44 < 3.5` 在 **agl 214** 就成立。也就是说：即使把 180 那条删掉，飞机仍会在 214 m 被强制改出——比它进入战斗的高度还高。这一条才是"没有战斗欲望"的物理来源，`tooLowToDive` 只是替它背了锅。

现在：几何判据降到 `minAlt+45`（只剩真正贴地的兜底），`recoverSeconds` 作为配置项暴露（2.2 s）。2.2 s 在下沉 44 m/s 时是 157 m AGL，仍然留足改出余量——150 m/s 从 17° 俯冲改平只需约 0.6 秒、13 m，加上约 0.5 秒控制延迟。巡航高度同时从 180 提到 **240**，让一次完整通过（俯冲 + 开火 + 拉起）落在改出线以上，并且越过 `yoyoMinAgl`(160)，机动库才有启动空间。

`desiredAltitudeAgl` 只影响**巡逻、编队归位、脱离后的爬升目标**；追击几何永远优先，所以把它调高不会让它在咬尾时飞得更高。

### 贴地救援：低速时越拉越掉

`mode=RECOVER` 里有一行"离地太近就无条件抬 17°"，本意是保命，实际是"贴地软脚"的制造者：

```java
if (agl < minAlt + 10.0) climb = Math.max(climb, 0.30);   // 旧代码
```

17° 爬升要能量。74 m/s 时 `alphaGuard = (speed − 0.55×corner)/(0.45×corner) ≈ 0.27`（corner = 0.85×130 = 110），抬头权限只剩 27%；ww3 的 FCS 又会把拉杆变成"钉在 `fcsMaxAOA`"，攻角一顶满、诱导阻力暴涨、速度继续掉。于是：**要求爬升 → 爬不上去 → 掉回地面 → 再要求爬升**。日志里这是连续三分钟的同一行：

```
su33 sinking: mode=RECOVER agl=0 vs=-10 spd=74 aoa=13.4 cmd(r/p/y)=-0.16/-1.00/0.54
```

现在的规则：**付得起才爬**。

| 能量 | `energyFrac = speed / cruiseSpeed` | 贴地（`agl < minAlt+10`）时 |
| --- | --- | --- |
| 够 | ≥ 0.65（≥ 84 m/s） | `climb = max(climb, 0.30)`，照旧拉起 |
| 不够 | < 0.65 | `climb = min(climb, 0.0)`——机翼放平、满油门，先把速度养回来再爬 |

第二种情况下它确实会继续掉一点高度（可能掉 30–60 格），但那是**唯一能活的路**：卸载 → 攻角降 → 阻力降 → 速度涨到 84 m/s 以上，下一帧就恢复成正常拉起。硬拉只会把最后那点能量烧在阻力上。

真正的根治不在控制律，而在**别让它落进这个状态**：空投高度。见第五章「部署器」一节。

### 开火模式门与瞄准判据

以前写死成两种模式：

```java
boolean attackMode = mode == Mode.PURSUE || mode == Mode.ENGAGE;
```

`MANEUVER` 被排除在外，而高 yo-yo、角点转弯这些动作**恰好**是在进到射击位置的那几秒里运行——一次通过里最好的一枪，正好撞在扳机被禁用的窗口上。现在 `MANEUVER` 放开，真正防住乱开枪的从来不是模式名，而是下面两道仍然生效的门：

- 锥角：`gunConeDeg`(6°) / `missileConeDeg`(25°)，误差要落在锥内；
- 距离带：所选武器的 `min`…`maxFireRange`。

所以机动中的开火只在"机头真的扫过目标且在射程带内"时发生——那就是一次 snap shot，本来就该打。模型的 `fire=false` 依旧是硬否决。

**`RECOVER` 从绝对禁区改成条件放行**（`fireInRecover`）。改出说的是**航迹**，不是机头：一架正在拉起、但机头仍指着目标 12° 的飞机完全具备发射条件。旧逻辑把 `!recover` 写成硬门，而低空交战时它几乎每一 tick 都在 `RECOVER` 里——这就是"整场一发弹都没有"的直接原因。现在 `RECOVER` 也能扣扳机，条件两个：`agl > minAlt + recoverFireAgl`(105)，以及下面那条瞄准判据成立。

**瞄准判据从"指令方向"改成"目标视线"**。旧代码量的是 `e`，也就是机头到 `desired`（本 tick 的操纵指令方向）的夹角。那不是目标所在的方向：lag pursuit 故意瞄在目标后方，`RECOVER` 的 `desired` 干脆是个爬升向量——两种情况下量到的都是错的角度（追击时偏松，改出时无意义）。现在直接算机头到目标的视线角：

```java
Vec3 losVec = (missile ? targetPos : aimPoint).subtract(v.position());
```

导弹打 `targetPos`（出膛无制导，要目标本身），机炮打 `aimPoint`（要提前量）。`diag` 行新增 `los(y/p)={}/{}`，就是这道判据用的两个角度——**这是唯一能回答"为什么不开枪"的数字**：`los` 在锥内而 `shots` 不涨，说明卡在距离带或 `allowFire`；`los` 超锥，说明机头没指过去。`-` 表示当前模式根本不做开火判定（`EXTEND`/`BREAK`/`NOTCH`），不是数据缺失。

### 低空通过高度：攻击为什么不能贴着目标飞

俯冲地板限制的是**角度**（最多 17°），不是**位置**。所以你飞 60–80 m 时，它会一路压到跟你一样高——然后跌进 `recover` 的门限（`minAlt + recoverSeconds × 下沉率`，−20 m/s 时约 104 m），整段通过都在强制改出里，扳机全程禁用。旧日志里 `agl=72/62/53、dist=479/510/542` 三行就是这个循环：**进射程时必在改出，爬出低空时已出射程，两个区间不重叠。**

`attackFloorAgl`(90) 把地板从"角度"升级成"位置"：`agl` 低于 `minAlt+90`（150 m）时，下降分量按 70 m 渐变淡出，到地板处完全归零，通过变成平飞。这不是放弃射击——那时目标在下方，90 m 高差配 400 m 水平距离是 13° 视线角，稳稳在 25° 导弹锥内。`0` 关闭该行为（回到旧版）。

两个旋钮的配合关系：`attackFloorAgl` 决定**在哪飞**，`recoverFireAgl` 决定**多低还能打**。前者治本，后者兜底；只调后者会让它在 105 m 贴着地面打，只调前者会在改出时仍然一枪不放。


### 相位机动

真实机动没法写成"朝某点飞"，因为它们**故意**离开瞄准点一会儿：高 yo-yo 要先拉起、保持高度、再压回来。所以内环之上加了一层相位机（`Maneuver`）：每个机动是一串阶段，每阶段有自己的指令和结束条件。

第一个接进来的是**高 yo-yo**（`mv=yoyo:PULL`）：

| 阶段 | 做什么 | 何时结束 |
| --- | --- | --- |
| `PULL` | 拉起脱离目标平面，同时朝它转弯，油门收到 0.45 | 高出目标 70 m，或接近率降到 60 m/s 以下 |
| `HANG` | 保持高度，0.35 秒 | 时间到 |
| `RE-ATTACK` | 按**当前**目标速度重算提前点，从上方压回去 | 距离 < 450 m 或 2.5 秒 |

触发条件用的是**剩余时间**而不是绝对接近率：`距离 < 450 m`、`接近率 ≥ 100 m/s`、`距离/接近率 ≤ 2.0 秒`。450 m 处 100 m/s 的接近率还有 4.5 秒余量，不需要 yo-yo；250 m 处同样的接近率只剩 2 秒，才是真的要让开。

硬性护栏：离地 < 160 m 不启动（后面要俯冲）、速度 < 1.4×最低速不启动、目标在头顶 80 m 以上不启动、总时长 5 秒封顶、结束冷却 60 tick。**地形保护和失速保护永远优先**——它们一拿走杆量，机动立刻中止，不会等你做完。只要本 tick 没进攻击分支（防御机动、巡逻、脱离、地面/起飞保护、失速卸载），相位机**立即中止而非冻结**；回到攻击分支后按新几何重新判定，不会带着旧相位和旧入场几何续跑。

### 机动库（12 个相位机 + 防御序列 + 巡逻航线）

同一时刻只有一架**攻击**相位机能拿杆量，按优先级挑一个；结束或中止后统一冷却 `yoyoCooldownTicks`。`status` 的 `mv=` 显示 `名称:阶段`，`mode=` 统一为 `MANEUVER`。防御序列与巡逻航线走独立通道，见本节末尾。

**build134 起 12 个攻击相位机全部默认开**：表中五个倒飞机动此前是关的，现在只是让它们的几何窗口开始参与竞争，优先级顺序、准入判据和租约一律没变。默认开不等于符号已验证，风险见本节末尾与第十三节。

| 机动 | 解决什么 | 阶段 | 默认 | 借上限 |
| --- | --- | --- | --- | --- |
| `yoyo` 高悠悠 | 接近率过大、要冲过头 | `PULL → HANG → RE-ATTACK` | 开 | 否 |
| `lowYoYo` 低悠悠 | 追不上、机头落在目标转弯后面 | `DIVE → TURN → RE-ATTACK` | 开 | 否 |
| `lagRoll` 位移滚 | 近距离仍有富裕接近率，但已超出高悠悠的距离窗 | `ROLL → DISPLACE → REACQUIRE` | 开 | 否 |
| `splitS` 半滚倒转 | 近距离僵局，快速掉头并降高换速度 | `ROLL → PUSH → LEVEL` | 开 | 否 |
| `sJink` S 型摆动 | 被咬尾 / 目标在侧后且接近，破对方提前量 | `TURN_A → TURN_B → REACQUIRE` | 开 | 否 |
| `cornerTurn` L 型角点转弯 | 远距目标偏离机头，抢内侧角度 | `IN → TURN → OUT` | 开 | 否 |
| `immelEscape` 置尾降高脱离 | 低速但还有余量，先水平掉头再降高换速 | `TURN → DESCENT → LEVEL` | 开 | 否 |
| `wingover` 跃升转向 | 高速高高度有富裕接近率，爬升换快速转向 | `PULL → TURN → LEVEL` | 开 | **是** |
| `barrelRoll` 防御桶滚 | 被纯追踪咬尾，用螺旋逼对方冲前 | `ROLL → LEVEL` | 开 | 否 |
| `spiral` 防御螺旋 | 低速被咬尾，滚转下降换速度 | `SPIRAL → LEVEL` | 开 | 否 |
| `immelmann` 标准半筋斗 | 高位反向，保高度换航向 | `PULL → HALF_ROLL → LEVEL` | 开 | **是** |
| `loop` 垂直筋斗 | 垂直面 360° 换航向 | `PULL → OVER_TOP → DIVE → LEVEL` | 开 | **是** |

**零豁免**的七个：纯下俯 / 水平，或下降段仰角为负。`limitClimb` 只压正的垂直分量、不压下俯；它们从不申请抬高机头姿态上限或爬升角。Split-S 需要显式 `bankSetpointDeg=180`，但下降段同样不需要抬姿态上限。`immelEscape` 名字容易误解：它借的是 `AircraftClass` 的「最大速率**水平**掉头 180° + 降高 + 改平」，**不是**半个垂直筋斗；标准半筋斗是表里另一个 `immelmann`。

**借上限**的三个（Wingover / Immelmann / Loop）必须同时申请 `requestCeilDeg`（机头姿态）和 `requestClimbCapDeg`（期望航迹的爬升角）。只抬前者没用：`limitClimb` 会先把 `desired` 压回 25°，内环根本看不到那个跃升。两项由同一份租约、同一笔高度/能量余量批准，一起单调收紧。

**持续滚转**的三个（桶滚 / 防御螺旋 / 标准半筋斗的半滚）用新增的 `rollRateCmdDeg` 通道。静态坡度目标会被 `wrap180` 夹到 ±180° 并最终稳定在某个角度，写不出连续 360° 滚转；这个通道直接给滚转率前馈，绕开坡度误差环，但滚转速率/角加速度/杆量 slew 三道限幅原样保留。控制器把它**串在 `lease.active()` 后面**：RECOVER、AGL 可疑、撤销冷却、余量耗尽时，这一项静默回落成普通的坡度控制律。

**防御序列** `defBreak`（`BEAM → REVERSE → RECOMMIT`）不走 `active`：LLM 选了 `break_left/right` 或 `notch` 时，由第二台相位机、第二个 `Ctx` 独立驱动，把原来「每 tick 重算一次 beam 方向」升级成「保持 beam → 反向横滚逼过冲 → 重新交战」。`attackBranch` 是安全层判定，**没有**为它改动；`mode=` 仍是 `BREAK`/`NOTCH`，`mv=` 显示防御阶段。两套调度都被租约逐 tick 监控。

**脚本档的 break：现在也走相位机（build122 起）。** 不接大模型时，break 由 `scriptFallback()`
决定方向，但**同样交给 `defBreak` 相位机执行** `BEAM → REVERSE → RECOMMIT`。此前这里有个
`!scriptDirectBreak` 的门，导致**不接模型时整段序列在代码层面不可达**，防御退化成「朝一侧
压一个固定坡度」——那就是「跟着它就一直左右翻、没有博弈感」的结构性原因。离线相位模型
（`tools/sim.sh run defense`）证明 74 m/s 也能完整跑完，所以这个门没有存在理由。
另外，安全层（`RECOVER`/起飞）抢占时**不再把序列清零**，只是暂停：下一 tick 地面一清空，
它从原来的相位继续，而不是从 BEAM 重来（低空改出循环比 2.5 秒的相位短，重来就永远到不了
REVERSE）。

脚本档方向仍然由下面三条规则给出（它们决定 `breakLeft/breakRight/notch`，不再决定姿态）：

- **侧向迟滞**：直接跟在正后方时，水平方位角落在 `atan2` 的 ±180 分支上，原来「方位 > 0 就右转」等于让几格的横向噪声每 tick 抛一次硬币，坡度指令还没等机身滚起来就反向 —— 这就是「跟着它就一直左右翻但航向不变」的成因。现在一侧选定后保持，直到目标进到机头前 `breakSideFlipDeg`(120°) 以内才允许改判，另有 `breakSideHoldTicks`(200) 兜底。
- **剪刀**：`scissorsRange`(450 m) 内、高度和速度够时，用**显式坡度 72°**（绕开 `bankLimitDeg` 的 65°）加收油门 0.50 的持续单向转弯。65° 坡度只有约 2.4 g、150 m/s 时 8°/s，机头掉过头要十秒；72° 收油后能翻倍。它仍是正飞坡度，不碰倒飞机动的符号表。
- **反咬**：目标被带到机头前方 `reversalBearingDeg`(100°) 以内就停止防御、转 `attack`。旧判据是 60°，而咬尾时方位是 180°，几何上永远不可能满足，所以被追的飞机只会一直逃、一枪不放。进入 / 退出各留 10° 迟滞加 30 tick 最小驻留，避免在阈值上来回切。

`mode=` 仍是 `BREAK`/`NOTCH`，`mv=` 现在会显示 `defBreak:阶段`（脚本档也走相位机了）。

> **`defBreak` 的低空门**：`agl < minAlt + defenseMinAgl` 或 `speed < minSpeed*1.3` 时不启动。
> 所以在贴地改出循环里它仍然不介入——那是**对的**（低空做防御桶滚只会更快撞地）。要让
> 它有机会介入，得先把高度和速度拿回来：收轮、平飞加速是唯一的路。

**巡逻航线** `PatrolPath`：只在「无目标、无编队槽位、无牵绳集结点」的自由巡航分支生效，把原来那个常数横向偏置乘上一条时间曲线 —— `eight`(8 字)、`racetrack`(跑道)、`constant_turn`(定常盘旋)。高度保持、能量衰减、编队保位全部没动。

**相位退出一律用时间、航向变化积分或垂直速度**，不用「机头到 X 度 / 坡度到 X 度」：限幅器一旦不让姿态到位，那种相位就永远不结束，等于把安全网永久关掉。垂直机动的顶点判据用 `verticalSpeed < 5`（可观测），不是机头角。

### 与模型层的联通（慢层约束，不是机动选择器）

**整套机动库不依赖大模型**。`chooseManeuver()` / `stepManeuver()` / `EnvelopeLease` 里没有任何 `modelLive` 判断，只读几何、配置、冷却和租约；脚本档、模型超时、决策过期时，12 个相位机、防御序列、巡逻航线和包线仲裁照常工作。模型层是**可选叠加的 0.5–2 Hz 慢层**，不是飞控的一环。

模型与机动之间只有三条通路：`attack` 放行 `chooseManeuver()` 按几何自选；`break_left/right` 与 `notch` 触发防御序列；`extend` / `patrol` / `bug_out` 关掉攻击相位机。另外 `desired_alt` 会改期望高度，间接影响租约的高度余量 `H`。模型**不点名具体机动**——2 s 的决策周期、1.5 s 超时与 0.3–3 s 的相位切换根本不同步，硬塞机动名只会被几何准入和租约否决，产出「下了指令没执行」的假反馈。

模型改用三个慢层约束表达意图：`posture`（balanced / aggressive / defensive / energy）、`allow_vertical`、`allow_inverted`。它们只在调度器**准入上加减条件**，默认全是中性值，不改变既有优先级顺序。反向的信息流也补齐了：态势 JSON 的 `ctl{}` 回传 `mode/mv/lease/ceil/cool/vs/att/bank/frz`，事件表新增 `maneuver_start/end`、`lease_revoke`、`recover`、`low_energy`，回合历史与复盘 transcript 带 `mv=`，战后条令多一个 `maneuver_bias`。详见第十章。

**相位边界冻结**：慢层在机动中途换动作曾会立刻 `abortManeuvers()` 腰斩相位机并锁租约 60 tick。现在新 action 只在相位结束那一 tick 生效，`status` 的 `frz=1` 表示旧动作被保持；低能量、低空和 RECOVER 立即解除冻结，安全层优先级不变。脚本档同样受益，因为 `scriptFallback()` 是每 tick 重算的。

### 包线租约：豁免与不坠机怎么共存

原来的问题是"给限幅器打个布尔洞"——一个标志同时摘掉爬升限幅和姿态上限两张网。现在改成**机动只提交意图，由独立的仲裁器逐 tick 裁决**（`EnvelopeLease`），执行顺序固定为：

`RECOVER/避地判定 → 攻击/防御相位机提议 → 能量看门狗 → 包线仲裁 → limitClimb → 内环`

仲裁器比上一版**提前到 `limitClimb` 之前**，只为一个原因：它现在同时批准「机头姿态上限」和「爬升角上限」，后者正是 `limitClimb` 的输入。它依然在 RECOVER 判定与能量看门狗之后，所以只能拿走权限、不能凭空给回；任何未批准的路径（无机动 / RECOVER / AGL 可疑 / 冷却 / 余量耗尽）两个上限都立刻回落到配置默认值，**默认飞行路径逐位不变**。

仲裁器每 tick 算三笔账，全部换算成米以便直接比较：

| 量 | 公式 | 含义 |
| --- | --- | --- |
| `H` | `agl − minAlt − 60` | 还能花掉的高度 |
| `H_exit` | `下沉率²/(2×15) + 速度×0.5` | **按当前下沉率**改出所需的距离，另加一个反应时间；比"距地还有 3.5 秒"更靠前 |
| `E` | `(v² − v_min²)/(2g)` | 可用动能折合的高度 |
| `spare` | `min(H − H_exit, E)` | 真正能借给机动的余量 |

三条硬规则：

1. **两个上限、同一笔预算、单调收紧**：`spare/300` 决定本 tick 能借多少，`ceil` 最多 `32+40°`、`climbCap` 最多 `25+30°`，都再与机动的申请值取小。一份租约内两者只减不增，掉高度或掉速度都不会把已交出去的权限还回来。
2. **fail-closed**：没有机动、`RECOVER` 生效、`aglSuspect`（高度读数可疑）、撤销冷却中、`enableEnvelopeLease=false` —— 任一成立，姿态上限回到 `maxPitchAttitudeDeg`(32°)、爬升上限回到 `maxClimbDeg`(25°)。AGL 可疑时宁可禁飞也不借高度。持续滚转通道另外串在 `lease.active()` 后面，租约一失效就自动退回普通坡度控制律。
3. **撤销即中止**：`spare ≤ 0` 时同 tick 中止两台相位机、清掉所有抬上限 / 显式坡度 / 持续滚转输出、进入 100 tick 撤销冷却，而不是等 3 秒能量看门狗在半空中把机动腰斩。机动自身的 60 tick 冷却负责防 RECOVER/机动抖动。

日志里每次授权/撤销都留痕：`[ww3ai] <机型> lease GRANT kind=... ceil=... climbCap=... H=... Hexit=... E=... spare=...` 与 `lease REVOKE reason=...`。`status` 有 `lease=`（`ACT:32` / `COOL` / `-`）、`ceil=`（本 tick 生效的姿态上限）、`climb=`（`limitClimb` 实际算出的爬升限幅角）。**Wingover 是第一个真正申请抬上限的机动**：build134 起 Immelmann 与 Loop 也默认开，三者都会让 `ceil=` / `climb=` 离开 32 / 25。桶滚与防御螺旋要租约批准但不申请抬上限，其余七个零豁免机动的 `ceil=` / `climb=` 恒为 32 / 25。租约对零豁免机动的作用仍是「逐 tick 监控并在余量耗尽时立刻收回机动」。

**已知限制**：`H_exit` 用的是**当前**下沉率。在机动顶点 `vs≈0` 时它只剩 `速度×反应时间` 这一项，不含"接下来会开始下沉"的预测——这是相对旧的 `secondsToFloor` 判据的改进，但不是完备的前瞻。Wingover 被选为租约第一次实战的试验品，正是因为它会在顶点附近经过这个薄弱区，但只需 45–50° 爬升、不倒飞、不碰未验证的控制符号；build134 起 Immelmann / Loop 已默认开，而它们的顶点正是这个薄弱区——在拿到实机日志标定 `a` / `t_react` 之前，别把租约余量当成可靠的保护。同理，速度接近 `minSpeed` 时 `E` 仍有小正值，租约只把上限压回接近默认值而不会直接撤销，此时仍由能量看门狗接管（离线复核：agl=800、50 m/s 时 `spare=24`、`ceil=35.2°`、`climbCap=27.4°`）。

**五个倒飞机动从 build134 起默认开，但风险一点没变**：`splitS`、`barrelRoll`、`spiral`、`immelmann`、`loop` 都要经过倒飞区，而 `SignTable` 的三轴符号只在正飞状态验证过（f15e = `1 -1 -1`）；倒飞时 pitch 通道相对世界系的符号会反，roll 符号一旦错就是正反馈滚到 180° 倒扣——正好是这些机动主动要去的地方。**出问题时一次只关一个开关**定位是哪台相位机，再按第十三节**逐轴二分**，绝不要三根轴一起翻，也不要一次改多个开关。Split-S 的 `PUSH` 阶段刻意顺着当前速度矢量飞、不主动下令世界系下俯，就是为了少碰这个未验证的符号区。Wingover 与 `immelEscape` 全程不倒飞，不需要这套额外验证。

标定常量 `PULLUP_ACCEL`(15 m/s²)、`REACTION_SECONDS`(0.5 s)、`TERRAIN_MARGIN`(60 m)、`MAX_EXTRA_DEG`(40°)、`MAX_EXTRA_CLIMB_DEG`(30°) 写在 `EnvelopeLease.java` 里而**不是**配置项：还没实机标定过，放进 toml 只会招来凭猜调参，而且运行中的游戏退出时会回写覆盖配置。拿到实机日志再改成常量即可。

### 数值验证

离线复刻内环（一阶航向响应 τ=0.9 s，130–230 m/s）：

| 场景 | 原固定 0.6 s | 三段律 |
| --- | --- | --- |
| 尾追 600 m / 接近率 200 / 目标 8°/s | 跟踪 2.5 s | **4.1 s** |
| 尾追 500 m / 接近率 260 / 目标 15°/s | 跟踪 1.6 s | 1.6 s（最近距离 17 m → 29 m） |
| 直线尾追 1400 m / 接近率 40 | 4.8 s | 4.8 s（**完全一致**，因为没有横向运动） |
| 横穿 800 m | 5.2 s | **7.4 s** |

最后一行是关键的自检：直线尾追必须和旧实现完全一样，否则说明提前量公式又跑到接近率上去了。

高 yo-yo 的离线结果**没有明显优势**（四个场景合计跟踪 13.1 s → 13.5 s）。原因是简化模型里航向响应不含过载代价——而 yo-yo 存在的理由正是"省下过载"，这个模型结构上无法体现。所以它默认开着但触发很保守；关注 `mv=` 是否在你觉得该让开时出现，不该出现时把它关掉（`[maneuver] enableHighYoYo=false`）。

## 十、模型到底在做什么

### 它看到的（每回合一份 JSON）

```json
{
  "self":   {"alt": 1820, "agl": 240, "spd": 210, "ammo": 340},
  "bandit": {"clock": 2, "rel_deg": 55, "dist": 1420, "closing": 85,
             "tail_aspect": 35, "alt_delta": -40, "spd": 195, "kind": "aircraft"},
  "threats": 0,
  "ctl": {"mode":"MANEUVER","mv":"yoyo:PULL","lease":"ACT:32","ceil":32,
          "cool":0,"vs":12,"att":18,"bank":35,"frz":1},
  "doctrine": {"throttle_bias":-0.05,"altitude_bias":80,"maneuver_bias":0.08,
               "samples":3,"note":"lost energy in every merge"},
  "event": "maneuver_start",
  "history": [{"a":"attack","mv":"lowYoYo:DIVE","d0":2100,"d1":1420,"hold":210}]
}
```

- `clock`：1–12 点方位，12 = 正前方，3 = 正右，9 = 正左，6 = 正后。
- `closing`：接近率，正数 = 距离在缩小。
- `tail_aspect`：0 = 敌机在逃（我们咬尾），180 = 迎头。
- `threats`：**除当前目标外**、1 km 内能打到我们的敌机数。
- `ctl`：20 Hz 控制层这一刻在做什么。`mode=RECOVER/UNLOAD/MANEUVER` 表示安全层或相位机已经拿走杆量，不是你的战术在执行；`mv=` 是当前机动与相位（`-` 为无）；`lease=` 是租约状态（`ACT:上限` / `COOL` / `-`）；`ceil=` 是实际批准的机头姿态上限；`cool=` 是还要等多少 tick 才能起下一个机动；`vs/att/bank` 是垂直速度、机头仰角、坡度；`frz=1` 表示你的 action 被保持到当前机动结束（见下）。**脚本档根本不构造这段 JSON**，零开销。
- `doctrine`：**当前生效的四个条令旋钮 + 上次复盘写下的经验 `note`**；`engage_range` 未设置时省略该键；`null` 表示这个模型从未被复盘过，一切从零开始。这是闭环的回灌段——模型能看到"我上次得出了什么结论、已经调到了哪"，避免每架次都从零调同一个方向。
- `event`：这次为什么叫它（心跳调用时为空）。除原有的目标/方位/射程/弹药/低空/开火事件外，现在还有 `maneuver_start/end`、`lease_revoke`、`recover`、`low_energy`。
- `history`：上几回合的"下了什么指令、哪个机动真的飞了、距离从多少变成多少"。`mv` 让你把距离变化归因到具体机动，而不是误判成自己的战术奏效或失效。

### 它能选的（7 个动作里选 1 个 + 五个参数）

| 动作                           | 什么时候用              | 控制器怎么执行     |
| ---------------------------- | ------------------ | ----------- |
| `attack`                     | 目标在前方扇区、能量充足       | 追瞄 + 进入射程开火 |
| `extend`                     | 速度太低、距离过近、需要重新拉起能量 | 拉开距离、保速度    |
| `patrol`                     | 没有目标               | 定高巡航        |
| `break_left` / `break_right` | 被咬尾、且对方接近很快        | 向对应侧做最大过载转弯 |
| `notch`                      | 有第二架逼近、或迎头远距       | 横切对方雷达视线    |
| `bug_out`                    | 没弹了、或高度危险          | 转头俯冲脱离，禁止开火 |

`desired_alt` 是高度增量（−300…300 m），`fire` 是开火许可。**只有 `attack` 且控制器自己判定进入锥角和距离带时才会真的扣扳机**——模型的 `fire=true` 是必要条件，不是充分条件。

还有三个**慢层约束**，它们不是机动名，模型永远不挑具体机动：

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `posture` | `balanced` / `aggressive` / `defensive` / `energy` | `balanced` 完全不改调度；`aggressive` 把租约支持的 Wingover 提前；`defensive` 禁垂直+倒飞；`energy` 只留保能量的水平/下俯相位机 |
| `allow_vertical` | true / false | false 禁 Wingover / Immelmann / Loop（这些要抬姿态上限） |
| `allow_inverted` | true / false | false 禁 Split-S / 桶滚 / 防御螺旋 / Immelmann / Loop（倒飞区符号未实机验证） |

**中性默认**：三个字段省略或解析失败时一律按 `balanced / true / true` 处理，即"不额外限制，完全听配置开关"。脚本档、模型超时、过期决策走的是同一套中性值，所以 `chooseManeuver()` 的默认路径与没有这套字段时**逐位一致**；调度器内部根本读不到 `modelLive`。约束只在下一次回复前有效，且永远不能覆盖避地/失速安全层。

**相位边界冻结**：以前模型（或每 tick 重算的脚本兜底）在一个 4–12 s 机动中途把 `attack` 换成 `extend`/`break`，会立刻 `abortManeuvers()` 腰斩机动并把租约锁 60 tick。现在新 action 只在相位结束的那一 tick 生效，`status` 的 `frz=1` 表示正在保持旧动作；`pst=` 显示当前态势与两个禁飞标志，`mb=` 是复盘调出的机动激进度。**低能量 / 低空 / RECOVER 会立即解除冻结**，安全层从不延迟。

### 四个自动机制

**事件触发**：不再死等心跳。目标出现/丢失、方位跨扇区、攻守易位、进入射程、弹药耗尽、低空，以及**机动开始/结束、租约撤销、RECOVER 接管、低能量看门狗启动**，任一发生就立即问一次。扇区变化要连续稳定 15 tick 才算数；租约撤销用单调计数器比较（有 100 tick 冷却），不会刷屏。

**控制状态回传**：态势 JSON 新增 `ctl{}`，把 `mode / mv / lease / ceil / cool / vs / att / bank / frz` 交给模型。之前模型只能看到距离变化，分不清"是我的战术起了作用"还是"20 Hz 飞控做了个低悠悠"，也看不到 RECOVER 已经接管——现在这两类误判都能避免。这段 JSON 只在真要发请求时才拼，脚本档一次都不执行。

**滚动记忆**：保留最近 4 个回合，每回合记录动作、**那一回合实际飞过的机动 `mv`** 与前后距离。模型能看到"attack + lowYoYo:DIVE 把距离从 2100 压到 1420"，也能看到连续两回合 `mv=-` 没进展，提示词要求它换招而不是重复。

**战后复盘**：一场战斗结束后，把决策记录（每行末尾带 `mv=`）+ 本场战果（击落数、开火数、接触目标秒数、剩余弹药）发回同一个模型，让它只调四个数：

```json
{"engage_range": 900, "throttle_bias": -0.05, "altitude_bias": 80,
 "maneuver_bias": 0.08, "note": "lost energy in every merge"}
```

`maneuver_bias`（−0.25…+0.25）只调**机动激进度**：正数让租约支持的 Wingover 更早参与竞争，负数压制它；它既不点名具体机动，也不放松安全层，0 时调度顺序完全不变。这四个数按 `provider/model` 存进 `data/ww3ai_doctrine.dat`，用 6:4 滑动平均收敛。旧存档没有 `maneuverBias` 键时读作 0，不会改变已有行为。下一次同模型的飞机起飞就带着新条令。`/ww3ai doctrine reset` 可全部清零。

**两种触发，`end` 说真话**：飞机被击落/消失时复盘（`end:"lost"`）；**活着打完也算**——无目标持续 `debriefCombatEndTicks`（默认 200 tick = 10 s）即判定战斗结束，同样复盘（`end:"survived"`）。修复之前的幸存者偏差：以前只有死掉的架次产生经验，且返航/玩家离开也一律标 `lost`；现在 `kills>0 + survived` 明确等于"打赢了，别乱动这条令"。**一场交战只复盘一次**：判定用的"停战"条件是单调的（一旦不再遇敌就永远成立），所以另外记了 `lastCombatSeenTick` 的水位线，必须比上次复盘时更新才会再触发——否则纯巡航的飞机会每攒够 6 个回合就发一次 `kills=0/survived`，几分钟内把条令刷成噪声。此外还要求**这一场至少接触目标 40 tick（2 秒）**：判"遇敌"用的是 `maxTargetRange`（默认 2000 格），敌机在边界来回时会出现单 tick 的闪现，而闪现同样会推进上面的水位线——不加这条，一架打完仗的飞机在边界有接触时又会每几十秒发一份 `kills=0`。真实交战、以及"追了很远但始终没进交战距离"的架次，接触时间都远超 2 秒，后者的"该拉长交战距离"经验不会被误吞。

**长架次按场复盘，四个数字同一个窗口**：`OUTCOME` 里的 `kills`/`shots`/`seconds` 全部是**上次复盘之后的增量**，`seconds` 数的是**接触目标的 tick** 而不是墙钟（一场 20 秒的交战 + 5 分钟巡航，报的是 20 秒，不是 5 分钟）。以前 `kills` 是增量、`shots` 是整段架次累计，第二场会输出"55 发 1 杀"，正好命中提示词里"打了很多发没战果 → 缩短交战距离"那条规则，把打得没问题的架次改坏；现在 `shots/kills` 是这一场的真实命中比。`freshRounds` 只数上次复盘之后的新回合（不够 `debriefMinRounds` 就不发）；注意它管的是**发的频率**，发出去的 transcript 始终是最近 `FLIGHT_LOG_MAX`(=20) 回合，可能含上一场的尾巴。

## 十三、故障排查

### 控制符号：逐轴二分，以及按机型记忆

三根轴各乘一个符号后写进 `inputX/Y/Z`（`rollSign / pitchSign / yawSign`），**彼此独立**。默认值 `1 / -1 / -1` 是在 f15e 上实测出来的。新机型对不上时，按现象一次只翻一根：

| 现象                                   | 该翻哪根 | 相对默认 `1 -1 -1` 的命令        |
| ------------------------------------ | ------ | ---------------------------- |
| 一路滚到倒扣（`bank` 单调爬向 180）        | roll   | `/ww3ai signs -1 -1 -1`      |
| 不倒扣了，但改出时越拉越低 / 直接扎地         | pitch  | `/ww3ai signs 1 1 -1`        |
| 转弯时侧滑、掉高度但不翻                    | yaw    | `/ww3ai signs 1 -1 1`        |

**不要一上来就 `/ww3ai signs 1 1 1`**：三根轴同时翻会修好 roll 又弄坏 pitch，从"倒扣"变成"直接俯冲"，看起来像换了个 bug。定下来之后用 `/ww3ai signs <r> <p> <y> <机型ID>` 按机型存盘。

按机型表写在 `config/ww3ai-signs.properties`（格式 `sign.f15e=1.0,-1.0,-1.0`），**独立于 Forge 的 `ww3ai-common.toml`**，所以不会被运行中的游戏退出时的配置回写覆盖。控制时按 `v.def.id` 查表，查不到才回落到全局运行时覆写 / `flight.*Sign`。`/ww3ai signs` 打印全表，`/ww3ai resetsigns all` 清空，`/ww3ai status` 首行 `signTypes=` 是已存机型数。每次接管的 `took over ...` 日志都带该机实际生效的 `signs=`，可直接核对。

## 十四、已知边界

- **模型层永不接管飞行**。它只给意图，网络问题最多让飞机"变笨"，不会让它失控。
- **ww3 的一个存档缺陷已被兼容层兜住**：`DoorsHandler.doors` 仅在首次 tick 初始化，未 tick 的载具存档必崩。
  本模组在存档事件里检测并补齐这一状态，不做 Mixin、不改 ww3 本体。
- **击杀判定基于 ww3 的生命状态，不是实体消失**（build136 起）：`HealthHandler.isDead()` 即 `state != OK`（SOFT_DEAD / HARD_DEAD）才是权威信号——ww3 把被击毁的飞机留在世界里，`isAlive()` 仍为 true，旧版因此一次 `KILL` 都打不出来，还把残骸当活机一直接管。`latest.log` 现在会打 `LOST <机型/UUID8> ... - releasing AI control` 与 `KILL jet=... bandit=... cause=SOFT_DEAD hp=0%`。归因条件仍是「上一 tick 锁定的目标 + 本机开过火 + 距离 ≤1500 m」，并按 bandit UUID 去重，同时开火只记一次；目标若在被发现前就被移除，仍可能漏记。所有 AI 逐机日志都带 `机型/UUID8` 短码，3v3 混战可以逐架区分。


- **`notch` 只有模型能用**：模组拿不到"导弹正在逼近"的信号，脚本层用 break/extend/attack 三档覆盖。
- **编队是"站位 + 分配"，不是完整四机战术**：没有数据链（每架用自己的雷达接触锁定）、没有交叉掩护/轮流攻击的显式规则、没有撞机规避。站位只在 `PATROL` 生效，一交战就解散——保持队形和打仗是互斥的。
- **长机是"几何基准"，不是指挥官**：你当长机时，模组只读你的位置/航迹/速度，不给你任何额外权限，也不会让僚机听你的战术口令。僚机只从管理器拿站位和分配结果；你没法说"二号去看六点"。
- **玩家的操控永远不被覆盖**：AI 不写你飞机的输入，所以"你当长机"完全靠你自己飞——飞得好，队形好看；一头扎地，僚机只能跟着你或者自己拉起。
- **AI 不会释放干扰弹**：`cms` 组件没有做反射封装，所以 AI 对红外弹没有 flare 防御、对雷达弹没有 chaff。你用红外弹打 AI 时它只会机动，不会放诱饵；反过来 AI 打你时，你的 flare 照样能骗掉它的弹（见「红外弹」一节）。
- **攻击角和过载只能"借"ww3 的**：`Ww3Api.aoaDeg()` 调的是 `RotationUtils.getPitchAngleOfAttack`，和 ww3 自己 FCS 用的是同一个函数，所以单位和 `criticalAOA`(17°) 同源；但模组拿不到 `fcsMaxAOA` / `fcsMaxG` 的当前生效值（只在 `Options` 里，运行时被内容包改写也不可知），所以"抬头权限按角落速度缩放"仍是**开环近似**：它保证低速不把杆打满，但不保证正好停在 FCS 的边界上。真要继续收紧，看 `aoa=` 而不是看杆量。
- **攻击地板降到 105 m 是"能打"，不是"不会撞"**：`recoverSeconds` 是**按当前下沉率线性外推**的，不做转弯半径/过载估计。陡俯冲（>35°）或倒扣时外推仍然偏乐观，真正的保护只剩俯冲地板（17°）和倒扣压俯仰两条。低空乱战时如果出现擦地，把它调回 3.0 而不是继续赖在 2.2。
- **`MANEUVER` 允许开火意味着它会在"脱离型"机动里也打**：`splitS` / `immelEscape` 的机头扫过目标时可能出现一枪。锥角和距离带保证这一枪是"真的指着"，但战术上它确实在一边转身一边射击——这是放宽模式门的代价，不想要就把那几条写死（`attackMode` 只有 `PURSUE`/`ENGAGE`）。
- **`attackFloorAgl` 把下降"淡出"，不是把高度"锁住"**：到 150 m 时垂直分量归零，变成平飞通过，所以它在正上方绕圈、不打下方目标这种情况是可能的（目标从机头下方穿出锥角后，它需要重新建立一次攻击航线）。90 m 高差配 400–600 m 水平距离约 9–13° 视线角，在 25° 导弹锥内；但**机炮锥只有 6°，平飞时基本打不到**——低空目标基本只能靠导弹。想让它在低空也能用机炮，把 `attackFloorAgl` 降到 40–60，代价是重新贴近改出线。
- **`fireInRecover` 会让它在真正危险的改出里也扣扳机**：门限是 `agl > minAlt + recoverFireAgl`(105)，而 `recover` 在 −20 m/s 下沉时约 104 m 就成立——两者几乎重合，所以它实际上只在"刚进改出"的一小段里能打，再低就自动禁枪。这个余量是靠两个配置值的差算出来的，改任意一个都要重新核一遍。
- **（历史结论，已过时）机动库只有一个动作**：早期版本只有高 yo-yo，当时判断「每个新机动都要一个相位类 + 一个触发条件，不是加个枚举就有的」。判断本身仍成立，但现已落地 12 个攻击相位机 + 防御序列 + 巡逻航线 + 包线租约（见第八章）。**脚本档的「剪刀」是单向持续转弯，不是真剪刀**：真剪刀是双方交替反转、速度一起掉到失速边缘；ww3 的俯仰速率上限 30°/s、72° 坡度下转弯半径仍有约 600 m，且缺少目标角速度观测，所以这里只做「收油 + 大坡度单向转 + 进到 100° 就反咬」。它能让对方冲过头、能把机头转回来开火，但不会出现两架飞机对着掉的画面。`scissorsBankDeg` / `scissorsThrottle` 是这一档的两个旋钮，掉速螺旋就先把坡度降回 68。
- **高 yo-yo 的收益未能在离线验证**：简化模型里航向响应不含过载代价（而 yo-yo 的原理正是省过载），所以仿真只能证明"触发收紧后不比原来差"（13.1 s → 13.5 s 跟踪时间），证明不了它更好。实机前把它当实验特性，`mv=` 出现得不合时宜就关掉。
- **追踪律依赖目标速度的一阶差分**：目标瞬移（重生、传送、载具切换）会带来一 tick 的假转弯率，最多让 `pur` 抖一次，下一 tick 恢复。已对转弯率做 90°/s 上限和 0.65 低通。
- **控制符号不是自动校准的**：默认 `1/−1/−1` 只在 f15e 上实测过，su33 等其它机型没有逐一验证。现在按 `defId` 查表（`/ww3ai signs <r> <p> <y> <机型ID>` 存到 `config/ww3ai-signs.properties`），混编机队可以给每个机型不同的值，但**判断哪根轴反了仍要靠人二分**；模组不会上电自测舵面响应。
- **模型调用有并发上限**（默认 2）。满载时新的请求会排队，不算失败，但决策会迟到。
- **蓝图与条令都是存档级**，换存档不共享。
- **AGL 是 heightmap 采样，不是射线测距**（build131 起）：地面真值取 `MOTION_BLOCKING_NO_LEAVES`，无线电高度表只在**回波严格低于飞机**时保守抬高地板；`getEffectiveFloorY()` 只作为更低的地板下界，不再当地面高度。代价有三：① 未加载区块的采样会返回世界最低高度，此时退回海平面 63，**在低于海平面的空域（洞穴、下界、深谷）可能读到负 AGL 并触发改出**；② 高度表回波 ≈ 飞机自身高度（刚生成、刚传送、尚未有回波）会被丢弃，建筑物上方的读数可能因此偏低一两帧；③ 生成净空复核同样只在已加载区块上生效。这些都不影响常规地表空域，但别把 `agl` 当成精确测高值。
- **生成错位只防"同点出生"，不是防撞系统**：`spawn.separation` 让连续生成的飞机错开坐标与高度，但交战中的汇聚、FOCUS 全队扑同一目标、以及只在 `PATROL` 生效的分离气泡仍然可能撞机——这一条边界没变。
- **油门目标与保护阈值已在 build137 拆成两个量**（解包 + 实机标定确认）：ww3 没有硬编码 `maxSpeed`，稳态平衡式是 `thrustCoef·P·T(v) = 5e-5·baseDragCoef·D(v)·gearMul·v²`（`T`/`D` 是 `thrustSpeeds`/`dragSpeeds` 折线插值，质量约掉）。解得收轮满油门极速 su33 101.7 / F-15 92.7 m/s；用实机 `in=1.00 & eng=ON` 最大速度（91 / 94）标定后，70% 油门稳态是 su33 77.2 / F-15 82.8。**`trimSpeed=80`** 只喂 `InnerLoop` 油门环和那条 WARN，让油门收敛在 0.7 附近而不再顶死 1.0；**`cruiseSpeed=130` 原样保留**，继续当 `energyFrac`、失速看门狗(80.6)、改出门槛(71.5)、角落速度(110.5) 的参考尺。**切勿把 `cruiseSpeed` 直接降到 80**：那会把改出门槛压到 44（低于 `minSpeed` 45，条件恒真），并让实测 70–94 m/s 的 `energyFrac` 变成 0.88–1.18，恒给 24° 强爬升 —— 正是 build135 修掉的低速 porpoise。另：`lease REVOKE reason=NO_MANEUVER` 源于机动最低进入速度被写死为 150–200 m/s，不归这两个配置管，本轮未动。
- **速率环增益在 build138 做了首次实机整定**：`ratePGain` 由 1.00 下调到 **0.60**（`rateIGain=0.8` / `attTauRoll=0.45` / `maxCmdRatePerTick=0.12` 一律未动）。依据：build137 首局 4 分钟打了 21 条 `elevator reversing` WARN，最高 19 次反向 / 20 updates，6 架 su33 全员中招，速度 56–80 m/s、`ctl.scale=1.00`、`cmd(p)` 顶到 ±1.00 满舵——速率环比例增益偏热的典型极限环；配置注释本来就写着 `buzzing stick -> 0.6`。这套值原本是在 build133 之前「roll 内环正反馈、靠外环和 SMAX 压住极限环」的时代整定的，符号修对后一直没重新做实机整定。**离线回归只证明没改坏别的**：S12/S9/S10/S11 全 PASS、S7 编队基线 `37s/41m/57m/2→2` 逐位不变、S6 recover 各档仍 `rev=0`；但 sim 不检测抖杆，0.60 是否真压住 buzz 必须看实机 A/B（WARN 条数 + 日志里的 `ratePGain=0.60`）。若转弯明显变钝，先回 0.8 再单开一轮，别把 `rateIGain`、`attTauRoll` 一起改。

## 十五、开发者：构建与部署

**禁止使用代理**，只用直连；确实连不上时改用国内镜像，也不要退回代理。

```bash
./build-direct.sh            # Git Bash
build-direct.cmd             # Windows 资源管理器双击亦可
```

脚本做三件事：清空所有 `*_PROXY` 环境变量、设置 `JAVA_TOOL_OPTIONS=-Dww3.debug=true -Djava.net.preferIPv6Addresses=true`、指向 PCL 自带的 JDK 17，然后 `gradle build --offline`。

为什么是 `JAVA_TOOL_OPTIONS`：Mavenizer 是 Gradle 拉起的**独立 JVM**（JDK 25），`org.gradle.jvmargs` 只作用于 Gradle 守护进程，传不进去；只有环境变量能被它继承。加上 IPv6 优先后，`launchermeta` / `piston-meta` / `maven.minecraftforge.net` 实测全部直连 200（约 1 s）。本机 `150.171.110.135:443`（Mojang CDN IPv4）超时，IPv6 `2603:1061:14:184::1` 正常——curl 默认走 IPv6 所以一直是通的，容易误判成"网络没问题"。

产物 `build/libs/ww3ai-1.0.0.jar`，部署目标：

```
.../versions/1.20.1-forge-47.4.29/mods/ww3ai-1.0.0.jar
```

若将来 IPv6 也被封：把 `https://maven.aliyun.com/repository/public` 加进 `settings.gradle` 的 `pluginManagement` 和 `build.gradle` 的 `repositories`，并把 `launcher_manifest.json` 预置到 `~/.gradle/caches/minecraftforge/forgegradle/mavenizer/caches/`。**任何情况下都不要在 `gradle.properties` 里写 `systemProp.*.proxyHost` 或加 `-Dhttps.proxyHost`。**
